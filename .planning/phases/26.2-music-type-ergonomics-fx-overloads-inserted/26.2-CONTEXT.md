# Phase 26.2: Music Type Ergonomics + FX Overloads — Context

**Gathered:** 2026-05-10
**Status:** Ready for planning

<domain>
## Phase Boundary

Make the music-type family — `Decibel`, `Beat`, `Cent`, `Semitone`, `Millisecond`, `Second`, plus the new `Hertz` — first-class at every FX call site. Composer should be able to write `(delay buf 250ms 0.5 0.4)`, `(compress buf -12dB 4.0 5ms 100ms)`, `(lowpass buf 800Hz)`, and `(volume buf 0.5)` and have the resolution + audio output be byte-identical with the bare-Double form they replace.

**ROADMAP entry has stale assertions** — by the time this phase starts, the following are ALREADY shipped (do NOT re-do):
- `Decibel.IsCompatibleWith(Double|Float)` ✓ (DecibelType.cs:23-27)
- `Beat.IsCompatibleWith(Double|Float)` ✓ (BeatType.cs:25-28)
- `Cent.IsCompatibleWith(Double|Float)` ✓ (CentType.cs:24-27 — the precedent)
- `Semitone.IsCompatibleWith(Int)` ✓ (SemitoneType.cs:22-25)
- `gain(Buffer, Decibel)` overload ✓ (EffectsFunctions.cs:296-298)

**Genuine work that lands in 26.2:**
1. Compat completeness — `Millisecond` and `Second` gain `IsCompatibleWith(Double|Float)`; cross-conversion `Ms↔Sec` stays as-is via `CanConvertTo`.
2. `gain` dB-vs-linear policy decided — split: `gain` stays dB-only, ship new `volume(Buffer, Double)` for linear multipliers.
3. Music-type overloads registered on every FX site where the param is conceptually musical: `delay` (Ms), `compress` (Decibel threshold + Ms attack/release), `sidechain` (Decibel threshold + Ms attack/release), `reverb` (Second decay).
4. `Hertz` type ships with `Hz` + `kHz` literal lexing, `IsCompatibleWith(Double|Float)`, and overloads on `lowpass`/`highpass`/`bandpass` filters AND `sine`/`saw`/`square`/`triangle` signal generators AND PitchConversion APIs.
5. Close the 2 pre-existing failing `DecibelBeatNumericCompatFacts` (`GainWith(Positive)?DecibelLiteral_…`) — type compat is in place but engine-eval source `(gain src -12dB)` still fails; investigate the `-12dB` / `+6dB` literal lexing path.
6. `ERG-01..ERG-04` REQUIREMENTS.md entries authored as part of phase closure (mirrors what 26.1 closure did for `DICT-01/02/03`).

**Out of scope (capture for a later phase):** Hertz `mHz` (millihertz) literal — no FX site needs it yet (LFOs aren't in the language); phase-vocoder time-preserving pitch shift; full Scala loader (deferred to v1.4 per D-03).

</domain>

<decisions>
## Implementation Decisions

### 1. Numeric compatibility (Ms / Sec / Semitone)

- **D-01:** `Millisecond.IsCompatibleWith(Double|Float)` and `Second.IsCompatibleWith(Double|Float)` both ship — symmetric with the Cent/Decibel/Beat precedent. `(delay buf 100.0 ...)` and `(delay buf 100ms ...)` both reach `Double` and `Millisecond` parameter slots.
- **D-02:** Existing `Millisecond.CanConvertTo(Second)` and `Second.CanConvertTo(Millisecond)` STAY. `(delay buf 0.1s ...)` continues to reach a `(delay buf, Millisecond, ...)` overload via convertible-score 100. Do NOT promote to `IsCompatibleWith` peers — the existing convertible path is enough and avoids overload-ambiguity risk.
- **D-03:** `Semitone.IsCompatibleWith(Int)` STAYS — semitones are whole-numbers-by-design. `(transpose seq 2.0)` reaches `transpose(Sequence, Cent)` (the existing cent-precision overload), not `transpose(Sequence, Semitone)`. Fractional pitch shifts go through Cent. Do NOT widen Semitone to Double/Float.

### 2. `gain` dB-vs-linear policy

- **D-04:** **Split the surface.** `gain` stays dB-only — both `gain(Buffer, Double)` (existing) and `gain(Buffer, Decibel)` (existing, shipped via QUICK-260504-w24) treat their second arg as decibels. New `volume(Buffer, Double)` ships and treats its second arg as a linear multiplier (0.5 = half-amplitude, 2.0 = double-amplitude). The function name documents the unit — composer chooses by semantic intent. Aligns with `feedback_charitable_interpretation`: silent-and-documented over magic.
- **D-05:** `volume(Buffer, Double)` is the single overload. `Float`/`Int` reach it via the existing primitive widening chain (Int → Long → Float → Double). No `volume(Buffer, Float)` separate overload — one registration covers all numeric inputs.
- **D-06:** Clipping behavior MIRRORS `gain` — accept any non-negative `Double`, print a stderr Warning when post-multiplication samples exceed 1.0 (`Warning: volume(N×) causes clipping. Consider reducing volume or applying compression first.`). Negative `volume` values rejected (volume can't phase-invert; that's a separate function-to-be-added later if needed). Implementation pattern: copy `EffectsFunctions.GainEffect` (lines 305-332) and replace `Math.Pow(10, dB/20)` with the bare-multiplier path.
- **D-07:** **No educational hint** when bare-`Double` `gain` is called with arg in `(0, 1)`. `(gain buf 0.5)` is a legitimate `0.5dB` attenuation. CLAUDE.md and Phase 27 tutorial.flow document the `gain=dB` / `volume=linear` split — composer who hits the footgun reads the docs. No runtime warning, no hint.

### 3. FX overload coverage

- **D-08:** Music-type overloads land on the following FX sites in 26.2:
  - `delay(Buffer, Millisecond, Double, Double) → Buffer` — full music-typed time param. Coexists with existing `delay(Buffer, Double, Double, Double)` (ms-rate Double, kept) and `delay(Buffer, NoteValue, Double, Double)` (Phase 22 DX-12, kept).
  - `compress(Buffer, Decibel, Double, Millisecond, Millisecond) → Buffer` — replaces threshold-as-Double + attack/release-as-Double with `Decibel` + `Millisecond`. Coexists with existing `compress(Buffer, Double, Double)` (simple) and `compress(Buffer, Double, Double, Double, Double)` (full).
  - `sidechain(Buffer, Buffer, Decibel, Double, Millisecond, Millisecond) → Buffer` — same shape as compress. Coexists with existing `sidechain(...)` Double-only overloads.
  - `reverb(Buffer, Double, Second) → Buffer` — decay-time as `Second` (typical 0.3s–3.0s). Coexists with existing `reverb(Buffer, Double)` (simple) and `reverb(Buffer, Double, Double)` (full). **Verify** that adding a `Second` overload does not ambiguate the simple `(reverb buf mix)` form — different arity should cleanly disambiguate.
- **D-09:** **Full music-typed overload only — rely on compat for mixed shapes.** Each FX function gets exactly ONE new music-typed overload (every musical param uses its music type). Mixed calls like `(compress buf -12dB 4.0 5ms 100.0)` resolve via the compat paths (Decibel→Double score 500, Ms→Double via the new D-01 IsCompatibleWith). No 2^N combinatorial explosion of overload registrations.
- **D-10:** **Decibel threshold overloads ship for `compress` and `sidechain`** — mirrors the `gain(Buffer, Decibel)` pattern from QUICK-260504-w24. Documents at the type-system level that the threshold IS a dB value.

### 4. Hertz type (ERG-04)

- **D-11:** **Hertz ships in 26.2.** New `HertzType` in `flow-lang/TypeSystem/SpecialTypes/`. Reading `Hz` / `kHz` literal lexing (mirrors `dB` / `ms` / `s` / `c` paths in SimpleLexer). `IsCompatibleWith(Double|Float)` — same shape as Cent/Decibel/Beat/Ms/Sec. Stored as a single canonical `double` Hz value (kHz multiplied by 1000 at lex time — no unit-discriminator at runtime).
- **D-12:** **Both `Hz` and `kHz` suffixes supported.** `800Hz` and `1.5kHz` both lex to single `HertzLiteral` tokens. `mHz` (millihertz) NOT shipped in 26.2 — defer until LFOs land in the language.
- **D-13:** Hertz overload coverage spans **filters + signal generators + PitchConversion APIs**:
  - `lowpass(Buffer, Hertz) → Buffer`, `highpass(Buffer, Hertz) → Buffer`, `bandpass(Buffer, Hertz, Hertz) → Buffer`
  - `sine(Hertz, Double) → Buffer`, `saw(Hertz, Double) → Buffer`, `square(Hertz, Double) → Buffer`, `triangle(Hertz, Double) → Buffer` (frequency param replaced; duration-Double stays)
  - PitchConversion-level APIs that take Hz numerically: planner verifies which surface them (likely `noteToFrequency` callers, `frequencyToNote`, etc.) — every `Double` param interpreted as Hz gets a `Hertz` overload.
  Composer who writes `(lowpass buf 800.0)` still hits the existing bare-Double overload via exact-match (score 1000) — bare-Double overloads NOT removed, only joined.

### 5. -12dB / +6dB literal closure

- **D-14:** Fix the 2 failing `DecibelBeatNumericCompatFacts` IN 26.2 scope (per STATE.md "Phase 26.2 owns closure"). Investigate why `(gain src -12dB)` engine-eval source still errors when the type compat + Decibel overload are both in place — likely the lexer doesn't form a single `DecibelLiteral` token from `-12dB` at expression-start, or the parser dispatch doesn't route the leading-sign prefix correctly. Fix lives in `flow-lang/Lexing/SimpleLexer.cs` and/or `flow-lang/Parsing/Parser.cs`. Same pattern applies to all music-type literals (`-100ms`, `-50c`, `+440Hz`, etc.) — fix once, document the rule, write regression facts for each suffix family.

### 6. Tests

- **D-15:** **Type-level + engine-eval pairs per overload**, mirroring `flow-lang.Tests/Unit/QuickFixes/DecibelBeatNumericCompatFacts.cs`:
  - For every new music-type overload registered (D-08, D-13): one `FunctionSignature.Matches(...)` type-level fact proving the music-typed arg resolves; one engine-eval fact running `.flow` source like `Buffer x = (delay buf 100ms 0.5 0.4)` and asserting per-sample identity with the bare-Double equivalent.
  - For every new IsCompatibleWith path (D-01, D-11): two type-level facts (Double + Float) per type.
  - For the gain/volume split (D-04..D-07): facts proving `(gain buf -12dB)` and `(gain buf -12.0)` produce identical samples; `(volume buf 0.5)` halves amplitude; `(volume buf 2.0)` doubles amplitude AND emits the clip warning.
  - For Hertz literal lexing (D-12): facts pinning `800Hz` and `1.5kHz` to the same `Value.Hertz(...)` representation (single canonical Hz double).
  - For -12dB literal closure (D-14): the existing failing facts in `DecibelBeatNumericCompatFacts.cs` flip to GREEN; add sibling facts for `-100ms`, `-50c`, `+440Hz`, `+6dB` each at expression-start position.
- **D-16:** Phase 18 `ByteIdenticalShowcaseTests` + Phase 25 `ByteIdenticalShowcaseGaussianTests` MUST stay GREEN. New overloads don't change resolution priority for existing bare-Double calls (exact-match wins over compat), so byte-identical contracts hold by construction. Verify in plan-level checks.

### 7. REQUIREMENTS.md authoring

- **D-17:** `ERG-01..ERG-04` requirements DON'T exist in REQUIREMENTS.md today. Plan must include a closure task that authors them — mirrors what Phase 26.1 closure did for `DICT-01/02/03`. Suggested split:
  - **ERG-01:** Music-type numeric compatibility completeness (D-01 + D-03).
  - **ERG-02:** FX overload registration on conceptually-musical parameter sites (D-08 + D-09 + D-10).
  - **ERG-03:** `gain` dB-vs-linear policy decision and `volume` shipping (D-04..D-07 + CLAUDE.md update).
  - **ERG-04:** `Hertz` type + `Hz`/`kHz` literals + filter/generator/PitchConversion overloads (D-11..D-13).
  - **ERG-05 (new):** `-12dB`/`-100ms`/etc. literal lexing at expression-start position (D-14).

### Claude's Discretion

- **Internal storage of Hertz** — single `double` field holding canonical Hz (kHz × 1000 at lex). No discriminator. Researcher may revise if there's a strong reason.
- **Compat helper consolidation** — if Researcher finds that 6 music types ALL implementing the same `IsCompatibleWith(Double|Float)` body warrants extracting a `NumericCompatible` mixin / base override, take that opportunity. Otherwise inline per-type per the existing pattern.
- **Reverb decay validation** — if `reverb(Buffer, Double, Second)` ambiguates the existing `reverb(Buffer, Double, Double)` overload via convertible-score, drop it and document. Different arity should cleanly disambiguate, but verify.
- **`-arg` literal lexing fix scope** — if D-14 closure is a deeper refactor than expected (e.g. requires reworking the Phase 26 D-02/D-04 single-token negative literal logic), Researcher flags it; planner may scope it to its own wave inside 26.2 or split to a follow-up. Don't drop scope silently.

<deferred>
## Deferred Ideas

- **`mHz` (millihertz) literal** — no FX site needs sub-Hz frequencies until LFOs land in the language. Defer to whatever phase introduces LFOs.
- **`volume` accepting negative values for phase-invert** — D-06 explicitly rejects negatives; if phase-invert turns out to be a recurring need, ship as a separate `invertPhase(Buffer)` function in a later phase, not via `volume`.
- **Auto-conversion of literal `100.0` in a Decibel-typed assignment context** (e.g. `Decibel x = 100.0` succeeding) — type-system question that goes beyond FX overload resolution. Out of scope; revisit if composers complain.
- **Hertz literal in note-stream context** (e.g. `| 440Hz |` as a frequency note rather than a Note literal) — different syntactic territory. Note-stream additions belong in their own phase.
- **`gain(Buffer, Float linear) + gain(Buffer, Decibel dB)` rename** — D-04 explicitly chose the function-name-based split (`gain` vs `volume`) over renaming. Don't revisit unless milestone retrospective surfaces composer pain.
- **Educational hint for `(gain buf 0.5)` style calls** — D-07 explicitly chose silent. Revisit only if user-research signal indicates the footgun is real.
