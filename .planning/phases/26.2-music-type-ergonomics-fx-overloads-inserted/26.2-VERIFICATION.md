## Open Questions Resolved

1. **PitchConversion Hz overloads** — RESEARCH Open Question #1 resolved: NO PitchConversion APIs added. `noteToFrequency` only RETURNS Hz, doesn't take Hz; no Hz-taking PitchConversion API exists in this codebase. ERG-04 acceptance text reflects this scope decision.

2. **`volume` convenience-layer wrapper** — RESEARCH Open Question #2 resolved: matches gain's shape. Single `internal proc volume(Buffer: b, Double: linearMultiplier)` line in `audio.flow` + matching C# registration in `EffectsFunctions.cs`. NO Flow-side convenience wrapper proc. Adding a Flow proc layer would add nothing and risk inadvertent clamping / scoping differences.

3. **Sine/saw/square/triangle Hertz overloads** — RESEARCH Open Question #3 resolved: extended existing `createSineTone` / `createSawTone` / `createSquareTone` / `createTriangleTone` family. `createSineTone` gets a C# Hertz overload (and a Flow-side proc shadow to deliver stereo); the other three get Flow-side proc overloads in `audio.flow` (Hertz auto-coerces to Double on the `createOsc` call via Wave-1 HertzType.IsCompatibleWith(Double) + Wave-0 Value.ConvertTo Double-arm). NO new short `sine` / `saw` / `square` / `triangle` builtins invented.

## Deviations Summary

Across the 5 implementation waves, **8 auto-fixed deviations** landed inline (all bugs / blocking issues / Rule-2 critical functionality). None required user input; none changed plan scope; all documented in their respective SUMMARY.md files. Notable patterns:

- **Plan-spec mismatch on AST shape** (Rule 1): Wave 2 plan example showed `LiteralExpression(HertzType.Instance, double, Location)` but the actual `LiteralExpression` is `record (SourceLocation, object)`. Followed existing music-literal pattern — raw-text in Parser, decode-in-evaluator. (Plan 26.2-03)
- **Type-name allowlist extensions** (Rule 3): Each new music type required `TypeParser.ParseType` + `TypeParser.TryParseSingularType` + `Parser.IsTypeKeyword` (singular AND plural form) + `Parser.IsArgumentStart` recognition. Same pattern as Phase 26.1's Symbol/Tuple/Dict additions. (Plan 26.2-03)
- **Mono-vs-stereo buffer mismatch** (Rule 2): C# `CreateSineTone` produces MONO; existing user-facing Flow proc produces STEREO via `createBufferStereo`. Added Flow-side proc shadow to re-route to stereo path. (Plan 26.2-04)
- **Test-assertion over-broadness** (Rule 1): `NegativeMs` assertion `stderr.Contains("Unexpected")` caught the runtime DSP wrapper `"Unexpected error: Delay time must be positive"`. Tightened to specific `"Unexpected token"` (lex/parse) + `"No matching overload"` (resolution) patterns. (Plan 26.2-04)
- **Test source amplitude** (Rule 1): Volume clip-warning fact used 0.5-amp sine doubled to 1.0 — never exceeded `> 1f` float threshold. Bumped to 0.8 amp so doubled samples reach ~1.6. (Plan 26.2-05)
- **Console.SetError parallelization** (Rule 2): VolumeFunctionFacts was the first test class to assert on a runtime-emitted `Console.Error.WriteLine`. Added `[CollectionDefinition("ConsoleCapture", DisableParallelization = true)]` to serialize this collection while preserving suite throughput. (Plan 26.2-05)

ALL deviations enumerated and audited in the per-wave SUMMARY.md files. Phase 18 + Phase 25 byte-identical regression contracts intact across every wave; full unit suite reaches 879/0/0 at Wave 4 close.
