## Decisions Made

1. **kHz checked before Hz in HertzType.Parse** — `EndsWith("Hz")` is true for any string ending in "kHz" too. Checking the longer suffix first prevents `1.5kHz` from being parsed as `1.5k` (which then fails as a Hz-numeric value). RESEARCH Pitfall 4 flagged this; implementation takes the documented ordering.
2. **Inline `IsCompatibleWith` per-type, no shared mixin** — RESEARCH Claude's Discretion was "if 6 music types ALL implement the same body, consider extracting." Math: 6 types × 2-line override = 12 LOC; mixin saves ~6 LOC at the cost of indirection. Not worth it. Inline matches the established Cent/Decibel/Beat precedent.
3. **`NumberStyles.Float` + `InvariantCulture` in Parse** — locale safety. CentType + DecibelType + MillisecondType + SecondType use the bare `double.TryParse(string, out double)` which is locale-aware (rejects "1.5" on de-DE). HertzType improves on the precedent — future Wave-2 lexer-driven Parse calls will see canonical en-US strings, but the explicit `InvariantCulture` keeps the contract robust if user code ever calls `HertzType.Parse(userInput)` directly. Not a regression of existing types; an additive improvement on the new one.
