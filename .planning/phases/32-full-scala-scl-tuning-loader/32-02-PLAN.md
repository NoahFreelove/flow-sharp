    Algorithm (single-pass, line-by-line with explicit `int lineNumber = 0; int column = 1;` tracking):

    1. Split content by `\n` (also handle `\r\n` — Trim trailing `\r` from each line). For each line, increment `lineNumber`.
    2. Skip lines whose first non-whitespace character is `!` (comments). Skip fully-blank lines BEFORE the description (RESEARCH A1 charitable). Capture the first non-skipped line as `Description` (trim trailing whitespace only — preserve leading whitespace per RESEARCH A2 NO, actually trim leading too since spec is silent and trimmed form is more useful for `(str t)` display).     3. After description, find the next non-comment non-blank line. Parse as a non-negative integer with `int.TryParse(trimmed, NumberStyles.None, CultureInfo.InvariantCulture, out int stepCount)`.     5. Allocate `double[] cents = new double[stepCount]`; `Dictionary<int, (int Num, int Den)> ratios = new()`.
    6. For each of the remaining `stepCount` non-comment non-blank lines, parse ONE step value (bounded loop `for (int i = 0; i < stepCount; i++)`). Algorithm per step:
       - Trim leading/trailing whitespace (spec allows leading space/tab on step lines).
       - Take the FIRST whitespace-delimited token of the trimmed line (per spec "Anything after a valid pitch value should be ignored" — this is how `100.0 C#` parses to `100.0¢`).

If parse fails OR token matches `[eE]` regex (defensive — `AllowExponent` exclusion is the primary guard) OR token contains `,` (comma-decimal — would be caught by InvariantCulture but assert defensively), throw `ScalaParseException(filePath, lineNumber, column, "cents value or ratio", token)`. Reject if not exactly 2 parts (rejects `3 / 2` because that's `3` followed by ` / 2` — only the first whitespace token is taken; the split-on-`/` then sees `3` which has no slash; reject as missing slash.     9. Return `new ParsedScala(description, cents[0..^1], cents[^1], ratios, filePath)`.
