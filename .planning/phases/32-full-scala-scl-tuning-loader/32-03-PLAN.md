## ResolvedTuning MidiToHz semantics — IMPORTANT, read before authoring tests

This plan uses **scale-step semantics**, NOT 12-TET semitone semantics, for the MIDI→Hz table. This is the natural Scala-format reading and aligns with how every other DAW Scala plugin behaves.

**The single anchor:** `MidiToHz[kbm.ReferenceNote] == kbm.ReferenceHz` EXACTLY by construction. With the default KBM (refNote=69, refHz=440.0), `MidiToHz[69] == 440.0` for every tuning. This is the cross-fixture invariant that tests anchor on.

**What this means for MidiToHz[60] (middle C in 12-TET):**

In 12-TET, A4=440 implies C4 ≈ 261.6256 Hz (440 / 2^(9/12)).
In a non-12-TET tuning, MidiToHz[60] is NOT 261.6256 Hz — it depends on what scale steps walking 9 steps below the reference (or 9 steps below middleNote depending on which is anchored) produces under the loaded .scl's step structure.

- For `partch_43` (43 steps per octave, first 9 steps span only ~165¢): walking from refNote=69 down 9 scale steps places middleNote at ~395 Hz, NOT 261.6256 Hz.
- For `slendro` (5 steps per octave, ~240¢ per step): walking 9 scale steps wraps through nearly 2 full periods, producing a different value again.
- For `carlos_alpha` (18 steps per period, period=1404¢, each step ~78¢): walking 9 steps spans ~702¢, producing yet another value.

**The test assertions therefore do NOT pin MidiToHz[60] to any 12-TET-derived value.** They pin:

1. The cross-fixture anchor: `MidiToHz[kbm.ReferenceNote] ≈ kbm.ReferenceHz` (= 440.0 for default KBM, ALL non-12-TET fixtures).
2. The internal-consistency invariant: `MidiToHz[middleNote + N_steps] / MidiToHz[middleNote] ≈ 2^(cents / 1200)` where cents is derived from StepCents/PeriodCents — this is the SPEC-5 acceptance form (carlos_alpha period wrap = 2^(1404/1200) ≈ 3.2003).
3. Per-fixture ratio Facts: e.g. for Partch, `MidiToHz[61] / MidiToHz[60] ≈ 81/80` (the first ratio in the .scl).

**The 261.6256 number that previously appeared in this plan's Behavior block was a 12-TET answer accidentally asserted against a non-12-TET tuning. It is removed.** The RESEARCH.md "Reference Hz values" section (lines 415-452) presents the same confusion in its commentary — the simplified "middleHz = 440 / 2^((69-60)/12) ≈ 261.6256" formula it shows assumes 12-TET semitones, which is wrong for a Scala tuning. The CORRECT formula (used by this plan's algorithm):

```
// Compute the scale-step "position" of refNote relative to middleNote, in cents under the loaded tuning
int refDegree = kbm.ReferenceNote - kbm.MiddleNote;       // e.g. 9 for default KBM
int stepsPerPeriod = StepCents.Count + 1;                 // e.g. 43 for partch
int refPeriodWraps = (int)Math.Floor((double)refDegree / stepsPerPeriod);
int refStepInPeriod = refDegree - refPeriodWraps * stepsPerPeriod;
double refCentsInPeriod = refStepInPeriod == 0 ? 0.0 : StepCents[refStepInPeriod - 1];
double refCentsFromMiddle = refPeriodWraps * PeriodCents + refCentsInPeriod;

middleHz = kbm.ReferenceHz × Math.Pow(2.0, -refCentsFromMiddle / 1200.0);
// Now MidiToHz[middleNote] = middleHz, and MidiToHz[refNote] = kbm.ReferenceHz by construction.
```

This is the algorithm described in Task 1's `<action>` block. The Behavior block below and the Fact assertions match this algorithm — anchor at refNote, derive all other positions via scale-step walking.
