## Three blockers (architectural, Rule 4)

### Blocker 1 — `(str Int[])` runtime crash (Wave 1 omission)

**Symptom:** Any `.flow` file that calls `(str someIntArray)` errors with
`Cannot convert Flow type 'Int[]' with underlying CLR type 'List`1' to
Flow target type 'Void[]'`. This is exactly RESEARCH §"Pitfall 2".

**Root cause:** `BuiltInFunctions.cs:197` registers `str(Void[])` as the
wildcard array overload. `EvaluateFunctionCall` matches `Int[]` to
`Void[]` via convertible scoring, then tries to coerce `List<Value>`
storage to `Void[]` target — no path exists.

**Effect:** `examples/tutorial.flow` cannot render at HEAD. Phase 18
`ByteIdenticalTutorialTests` Wav + Mid both fail.

**Fix scope:** ~30 LOC in `flow-lang/Interpreter/ExpressionEvaluator.cs`
(or wherever `EvaluateFunctionCall` lives). Two options:
- **Option A (preferred per RESEARCH):** add a coercion pass after
  `_context.TryResolveFunction` — for each arg whose runtime `FlowType`
  differs from the matched signature's parameter type, call `ConvertTo`.
- **Option B:** special-case `Void[]` parameter type to be a true
  pass-through wildcard that bypasses `ConvertTo`.

**Reproduction (no migration needed):**
```bash
cat > /tmp/repro.flow <<'EOF'
use "@std"
Int[] xs = [1, 2, 3]
String s = (str xs)
(print s)
EOF
dotnet run --project flow-interpreter /tmp/repro.flow  # error
```

### Blocker 2 — Showcase WAV cross-HEAD digest legitimately differs (squash side-effect)

**Symptom:** Pre-baseline (HEAD~2 = `dce86f1`) `flow_showcase.wav` digest
`92aed72d…`. Post-migration (HEAD-with-walker-fixes) `flow_showcase.wav`
digest `9e00d7f9…`. MID digest matches exactly.

**Root cause:** Commit `86fa69a` squashed Phase 26 waves 0–2 PLUS three
quick-task hot fixes, including "scale ADSR envelope to note duration
so short notes have a release tail" (commit message). The ADSR change
deliberately alters audio output. So the cross-HEAD baseline cannot
match no matter what Wave 3 does.

**In-session determinism IS preserved:** two consecutive runs at HEAD
both produce `9e00d7f9…`. Phase 18 `ByteIdenticalShowcaseTests`,
Phase 23 `ByteIdenticalDefaultTuningTests`, and Phase 25
`ByteIdenticalShowcaseGaussianTests` all PASS. The D-14 contract
("byte-identical determinism") holds in-session; only the cross-HEAD
comparison protocol from `26-04-PLAN.md` is broken.

**Why it can't be bisected away:** Wave 1 banned infix arithmetic, so
the post-Wave-1 parser requires `flow-lang/audio.flow` and
`flow-lang/composition.flow` to be migrated to prefix form. composition
imports audio, so neither can be reverted in isolation — both must be
in prefix form for showcase to render at all. There is no migrated
state in which showcase reads the un-migrated stdlib.

**Fix scope:** planner decision (Rule 4):
- **Path A (lower friction):** declare D-14 met by Phase 18/23/25
  in-session ByteIdentical xUnit guards alone. Drop the cross-HEAD
  SHA256 comparison from `26-04-PLAN.md` Task 2 Steps A–C. Document
  the ADSR shift in the new fix-phase plan as a known semantic
  consequence of the squash.
- **Path B (preserves cross-HEAD):** when retrying Wave 3, capture
  pre-baseline against HEAD-pre-migration (after Blockers 1+3 are
  fixed but BEFORE the migrator walks the .flow tree), not against
  HEAD~N. Showcase digest will match because the post state is
  in-session deterministic — the comparison just needs to be against
  the same ADSR-fixed parent.

### Blocker 3 — D-08 `(div Int Int) -> Double` exposed via migration

**Symptom:** Files with `Int x = a / b` (truncating Int division)
migrate to `Int x = (div a b)`. Per Wave 1 D-08, `(div Int Int)`
returns Double, so the assignment errors with
`Cannot assign Double to variable of type Int`.

**Affected files (visible during the Wave 3 attempt's smoke loop):**
- `tests/test_comments.flow:35` — `Int d = a / b`
- `examples/long_demo.flow:356` — `Int mainSec = totalDuration / sectionCount`
- (plus more — smoke loop reported 46 failures, several share this
  signature; Blocker 1 caused most of the remainder.)

**Root cause:** D-08 is intentional Wave 1 design. The migrator
faithfully translates `a / b` to `(div a b)` — it doesn't know whether
the user intended truncating or floating division. RESEARCH §"Migration
Targets" did not enumerate the `(div Int Int) -> Double` interaction
with type-annotated assignments.

**Fix scope:**
- **Option A (hand fix):** grep for `Int [a-zA-Z_]+ = \(div ` after
  migration; replace `(div` with `(idiv` at each Int-typed assignment.
  Minimal new code; explicit per-site review.
- **Option B (smarter walker):** add a post-rewrite pass to
  `Migrate26/Program.cs` that scans declarations and rewrites
  `Int IDENT = (div EXPR EXPR)` to `Int IDENT = (idiv EXPR EXPR)`.
  More robust but adds AST awareness to the walker.
