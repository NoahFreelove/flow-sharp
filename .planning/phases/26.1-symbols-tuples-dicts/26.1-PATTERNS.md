#### B1. `flow-lang/TypeSystem/SpecialTypes/TupleType.cs` (NEW)

**Analog:** `flow-lang/TypeSystem/ArrayType.cs` (full file, 64 lines — generic-of-1 with element-type tracking, structural Equals, AnyArity-via-Void wildcard).

**Excerpt** (`ArrayType.cs:1–63`):
```csharp
namespace FlowLang.TypeSystem;

/// <summary>
/// Represents an array type with an element type.
/// </summary>
public sealed class ArrayType : FlowType
{
    public FlowType ElementType { get; }

    public ArrayType(FlowType elementType)
    {
        ElementType = elementType ?? throw new ArgumentNullException(nameof(elementType));
    }

    public override string Name => $"{ElementType.Name}[]";

    public override bool Equals(FlowType? other)
    {
        return other is ArrayType arrayType
            && ElementType.Equals(arrayType.ElementType);
    }

    public override int GetHashCode()
    {
        return HashCode.Combine(GetType(), ElementType);
    }

    public override bool IsCompatibleWith(FlowType target)
    {
        // Arrays are compatible if element types are compatible
        if (target is not ArrayType targetArray)
            return false;

        // Special case: Void[] is compatible with any array type (empty arrays)
        if (ElementType is PrimitiveTypes.VoidType)
            return true;

        // Special case: Void[] target accepts any array type
        if (targetArray.ElementType is PrimitiveTypes.VoidType)
            return true;

        return ElementType.IsCompatibleWith(targetArray.ElementType);
    }

    public override bool CanConvertTo(FlowType target)
    {
        // Arrays can convert if element types can convert
        if (target is not ArrayType targetArray)
            return false;

        if (targetArray.ElementType is PrimitiveTypes.VoidType)
            return true;

        return ElementType.CanConvertTo(targetArray.ElementType);
    }

    public override int GetSpecificity()
    {
        return ElementType.GetSpecificity() + 50;
    }
}
```

**Mirror:**
- Constructor takes `IReadOnlyList<FlowType> ElementTypes` (per-position) instead of a single `ElementType`.
- `Equals` does per-position comparison: `other is TupleType t && ElementTypes.SequenceEqual(t.ElementTypes, FlowTypeEqualityComparer)`. (RESEARCH § Q11 verified that `Utils.StrictEquals` already handles tuples-as-IReadOnlyList<Value> at the value level — TupleType only needs to handle TYPE-level equality.)
- `GetHashCode` combines `GetType()` with each element type.
- `IsCompatibleWith` does per-position compatibility, plus an `AnyArity` sentinel that matches any tuple.
- `GetSpecificity()` returns `ElementTypes.Sum(e => e.GetSpecificity()) + 60` (slightly more specific than ArrayType because tuples carry per-position type info).

**Differ:**
- Add `IsHashable()` override: `return ElementTypes.All(e => e.IsHashable());` — recurses, satisfies CONTEXT § Hashable enforcement.
- Add `public static TupleType AnyArity { get; } = new(EmptyList, isAnyArity: true);` sentinel for `(unpack)` registration (RESEARCH § Q6/Q7). Mirror `ArrayType(VoidType.Instance)` as the wildcard convention but use a dedicated `IsAnyArity` flag so the wildcard doesn't collide with the legitimate `Tuple<<Void>>` case (extremely rare but possible).
- Empty-tuple (`Tuple<<>>`) and singleton (`Tuple<<T>>`) are valid: `ElementTypes` may be empty or single-element. The constructor should NOT reject these.

#### E4. `flow-lang/Runtime/DictKeyComparer.cs` (NEW)

**Analog:** RESEARCH § Code Examples — full implementation directly authored (lines 768–797). In-repo precedent for the Equals dispatch: `flow-lang/StandardLibrary/Utils.cs:90 StrictEquals` (recursive structural equality on `Data is IReadOnlyList<Value>`).

**Excerpt — RESEARCH § Q9 verbatim:**
```csharp
public sealed class DictKeyComparer : IEqualityComparer<Value>
{
    private readonly FlowType _keyType;
    public DictKeyComparer(FlowType keyType) => _keyType = keyType;

    public bool Equals(Value? a, Value? b)
    {
        if (a is null || b is null) return ReferenceEquals(a, b);
        // Float NaN special case — Dict-internal only.
        if (_keyType is FloatType && a.Data is double ad && b.Data is double bd)
        {
            if (double.IsNaN(ad) && double.IsNaN(bd)) return true;
            return ad == bd;
        }
        // Symbol pointer-equality fast path.
        if (_keyType is SymbolType) return ReferenceEquals(a.Data, b.Data);
        // Default: delegate to existing structural equality.
        return Utils.StrictEquals(a, b);
    }

    public int GetHashCode(Value v)
    {
        if (v.Data is double d && double.IsNaN(d)) return 0;
        return v.Data?.GetHashCode() ?? 0;
    }
}
```

**Differ from the RESEARCH excerpt:** Add a `TupleType` branch BEFORE the default — recursively compare per-position using a sub-comparer parameterized by each element's type (so a `Dict<Tuple<<Float, Int>>, V>` correctly NaN-special-cases the Float component).

**Critical (RESEARCH § Pitfall 3):** This comparer is the ONLY place that touches NaN-equals-self. `Utils.StrictEquals` is NEVER modified. The general `(equals nan nan) → false` invariant outside Dict is preserved.
