## Deviations Summary

Across the 5 implementation waves, **20 auto-fixed deviations** landed inline (3 in Wave 1, 4 in Wave 2, 5 in Wave 3, 8 in Wave 4) — all bugs / blocking issues / Rule-2 critical functionality. None required user input; none changed plan scope; all documented in their respective SUMMARY.md files. Notable patterns:

- **Plan-vs-grammar adaptations** (Rule 1): Plans referenced `<<C4, q>>` idioms relying on a non-existent top-level `Beat q` constant. Wave 2 substituted Note+Note pairs in facts/smoke; Wave 4 added a `(beat Double)` constructor builtin to enable the original idiom.
- **Lexer expression-start gate extensions** (Rule 3): The plan's gate set for Wave 2's `LessLess`/`GreaterGreater` did not include `LessLess` itself, breaking empty-tuple `<<>>`. Auto-added with explanatory comment; note-stream `>` regression preserved by the PeekNext-equality short-circuit.
- **`Parser.IsTypeKeyword` allowlist** (Rule 3): Each new type-annotation keyword (Symbol, Tuple, Dict) required adding to `Parser.IsTypeKeyword` (the variable-declaration gate) IN ADDITION to `TypeParser.ParseType`. Same pattern across Waves 1-4.
- **Wildcard-type skip-coerce** (Rule 3): Wave 4 extended the `ExpressionEvaluator.EvaluateFunctionCall` arg-coercion skip list to cover `DictType{KeyType:Void, ValueType:Void}` and `TupleType{IsAnyArity:true}`, mirroring Phase 26 fix-omissions Blocker 1's `ArrayType{ElementType:Void}` skip.
- **Critical missing functionality** (Rule 2): `(str Symbol)` overload, `Interpreter.CreateDefaultValue` `TupleType` recursion, BeatType / DoubleType `IsHashable=true`, `(beat Double)` constructor. All called out in the plans' acceptance shapes but absent from the action-step lists.

Pre-existing `DecibelBeatNumericCompatFacts` (2 failures) remained out of scope per executor SCOPE BOUNDARY rule — they were RED at parent commit `95bd946` before any Phase 26.1 work. Phase 26.2 (Music Type Ergonomics + FX Overloads) is scoped to close them.
