## Decisions Made

- **Dict<Void, Void> wildcard for proc declarations:** the simplest way to make OverloadResolver pick the Dict-side `(each)`/`(map)`/`(filter)` impl over the Array-side at runtime. The TypeParser exempts VoidType key from IsHashable enforcement (defensive constructor also exempts it). User-facing source paths never hit Void key because typing requires concrete K at variable annotation sites.
- **(beat Double) over user-source `q`/`h` constants:** keeps the dict tests authentic (CONTEXT block 9 says `Dict<Tuple<<Note, Beat>>, Int>` should work) while not requiring Wave 4 to invent top-level Beat literals — that follow-up was already noted in Wave 2 SUMMARY.
- **Empty Dict<Void, Void> → Dict<K, V> rekey at assignment:** `(dict)` returns Dict<Void, Void> (no key/value type info available); the assignment site narrows it to the annotated `Dict<String, Int>` etc. by re-keying with the target's KeyType comparer. Mirrors Void[] → T[] precedent.
- **DictData equals `(merge)` order = "this then other (last-write-wins; this's positions preserved)":** locks CONTEXT § Claude's Discretion D-claude-merge into the implementation.
- **Map V-only transform:** key-remap deferred (RESEARCH § Open Questions Q2 RESOLVED). `(map d cb)` returns `Dict<K, V'>`; if callback returns heterogeneous types, V' degrades to VoidType (mirrors Collections.Map convention).

**1. [Rule 3 - Blocking] Parser.IsTypeKeyword missing "Dict"**

**2. [Rule 3 - Blocking] ExpressionEvaluator coerced Dict<K, V> args to Dict<Void, Void>**
- **Found during:** Task 2 smoke-test — `(get d k)` failed with "Cannot convert Flow type 'Dict<Symbol, Int>' with underlying CLR type 'DictData' to Flow target type 'Dict<Void, Void>'".
- **Issue:** `EvaluateFunctionCall`'s arg-coercion loop (line 219) tried to ConvertTo each arg to the registered sig's InputType. For Dict<K,V> arg → Dict<Void,Void> wildcard target, `Value.ConvertTo` has no Dict→Dict path and threw `InvalidCastException`. Existing skip for `ArrayType{ElementType:VoidType}` (Phase 26 fix-omissions Blocker 1) covered Array but not Dict / Tuple.
- **Fix:** Extended the skip list in `ExpressionEvaluator.EvaluateFunctionCall` to include `DictType{KeyType:VoidType, ValueType:VoidType}` and `TupleType{IsAnyArity:true}` — both are dispatch-only wildcards used by RegisterDict (Dict ops) and RegisterDict (`(unpack)`) respectively. Mirrors the existing Void[] skip pattern.
- **Files modified:** `flow-lang/Interpreter/ExpressionEvaluator.cs`
- **Verification:** `(get d k)` smoke-test passed; all 14 dict ops then worked end-to-end.
- **Committed in:** daaa023 (Wave 4 mega-commit)

**3. [Rule 3 - Blocking] std.flow varargs declarations used `Voids:` plural-form which translates to ArrayType(Void), not Void with IsVarArgs=true**
- **Found during:** Task 2 smoke-test — `dictTuple` declaration produced "No C# implementation found for internal proc 'dictTuple' with signature dictTuple(Void[])" because the registered impl had `[TupleType.AnyArity]` IsVarArgs=true while the declaration produced `[Void[]]` IsVarArgs=false.
- **Fix:** Changed `(Voids: pairs)` to `(Void...: pairs)` (ellipsis varargs syntax — same form `internal proc list (Void...: items)` uses in collections.flow). Same change for `dictTuple`.
- **Files modified:** `flow-lang/std.flow`
- **Verification:** `(dict #kick 90 #snare 70)` matched the registered varargs Void impl.
- **Committed in:** daaa023 (Wave 4 mega-commit)

**4. [Rule 3 - Blocking] std.flow `(each)`/`(map)`/`(filter)` declarations conflicted with existing Array-typed declarations in collections.flow**
- **Found during:** Task 2 smoke-test — `(each Dict, Function)` reported "No matching overload" because the Wave 4 std.flow declaration `each (Void: d, Function: cb)` matched the FIRST registered impl (Array `[Void[], Function]`) at proc-declaration time, replacing the Array overload's FunctionOverload entry.
- **Fix:** Changed the Wave 4 std.flow declarations to use `Dict<Void, Void>: d` instead of `Void: d` for the dict slot. This forces TryGetImplementation to skip the Array-typed impl (registered=`[Void[], Function]` doesn't match requested=`[Dict<Void,Void>, Function]` at the InternalFunctionRegistry.TypesEqual level). Required exempting VoidType keys from TypeParser's IsHashable gate (DictType constructor already exempted them).
- **Files modified:** `flow-lang/std.flow`, `flow-lang/Parsing/TypeParser.cs`
- **Verification:** `(each Dict<Symbol, Int>, Function)` now resolves to DictFunctions.Each; Array each (`[Void[], Function]`) remains accessible for Array args.
- **Committed in:** daaa023 (Wave 4 mega-commit)

**5. [Rule 3 - Blocking] `Dict<String, Int> d = (dict)` failed because empty (dict) returns Dict<Void, Void>**
- **Found during:** Task 3 fact run — `GetOr_ReturnsDefault` and similar tests using empty `(dict)` failed with "Cannot convert Flow type 'Dict<Void, Void>' with underlying CLR type 'DictData' to Flow target type 'Dict<String, Int>'".
- **Fix:** Added empty Dict<Void, Void> → Dict<K, V> rekey path in `Value.ConvertTo` (mirrors Void[] → T[] precedent for empty arrays). The empty DictData is rebuilt with the target type's KeyType comparer.
- **Files modified:** `flow-lang/Runtime/Value.cs`
- **Verification:** All Dict-typed variable assignments accept the empty dict literal.
- **Committed in:** daaa023 (Wave 4 mega-commit)

**6. [Rule 2 - Critical] BeatType / DoubleType IsHashable=true (DICT-01 acceptance)**
- **Found during:** Task 3 fact run — `AllowedKeys_TupleOfHashables` failed because `Dict<Tuple<<Note, Beat>>, Int>` rejected at parse time (Beat not hashable). Same for the Float Theory row using `1.0` (lexes as Double, not Float; Double wasn't hashable).
- **Issue:** Plan's CONTEXT block 9 acceptance shape `Dict<Tuple<<Note, Beat>>, Int>` requires Beat to be hashable. By symmetry with Float (already hashable), Double should also be hashable — they're both numeric value-equal types backed by `double`.
- **Fix:** Added `public override bool IsHashable() => true` to both `BeatType.cs` and `DoubleType.cs`. The TypeParser allowlist error message wasn't changed — it still names the original 8 types because Beat/Double are conceptually subsumed by "Float" in the user mental model.
- **Files modified:** `flow-lang/TypeSystem/SpecialTypes/BeatType.cs`, `flow-lang/TypeSystem/PrimitiveTypes/DoubleType.cs`
- **Verification:** `AllowedKeys_TupleOfHashables` and `AllowedKeys_Inline(Double, ...)` GREEN.
- **Committed in:** daaa023 (Wave 4 mega-commit)

**7. [Rule 2 - Critical] (beat Double) constructor builtin (DICT-01 Tuple-of-hashables)**
