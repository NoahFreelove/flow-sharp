## Decisions Made

- **Removed plan's `IsTokenBoundary` `#` addition.** The plan listed `or '$' or '#'` as the acceptance criterion for SimpleLexer.cs:932-937, but adding `#` to `IsTokenBoundary` BREAKS existing `C#4`, `F#4`, `G#5` sharp-note literals because `ScanIdentifierOrKeyword` calls `IsTokenBoundary` to detect end-of-identifier — note literals rely on `#` being absorbed mid-identifier. The `case '#':` arm in `NextToken` is sufficient on its own: when `#` starts a token, the switch case fires and reads `#identifier` as a SymbolLiteral; when `#` appears INSIDE an identifier (e.g. `C#4`), control is already inside `ScanIdentifierOrKeyword` (which never re-enters `NextToken`), so the switch arm doesn't trigger and `#` is correctly absorbed. The lexer comment on lines 666-668 (Phase 14 DX-06) explicitly documents this absorption behavior. Discovery: Phase 18 `ByteIdenticalTutorialTests.Tutorial_TwoRunsProduceIdenticalWav` failed at `examples/tutorial.flow:403` with `Empty note stream` — line 403 contains `Sequence sharps = | C#4 F#4 G#5 |`. Fix: revert the IsTokenBoundary edit; add explanatory comment in its place.

- **Auto-added `(str Symbol)` overload.** The plan didn't mention `(str)` for Symbol but the test_symbol_literal.flow script (per CONTEXT § Specifics block 1) requires `(str kick)`. Without it, the OverloadResolver rejects with `No matching overload for function 'str' with argument types (Symbol)`. Implemented via new `StdLib.StrSymbol` (returns `"#" + name`), registered in `BuiltInFunctions.cs`, and declared in `std.flow` as `internal proc str (Symbol: value)`. Output matches source form (e.g. `(str #kick) → "#kick"`).

- **Auto-added "Symbol" to Parser.IsTypeKeyword.** The plan added "Symbol" to TypeParser (the type-annotation parser) but missed `Parser.IsTypeKeyword` (the gate that triggers `ParseVariableDeclaration` when seeing `Symbol kick = ...`). Without this, `Symbol kick = #kick` fails to parse — the parser sees `Symbol` as a regular identifier and tries to interpret the line as an expression, hitting `=` unexpectedly. Added "Symbol" to both the singular allowlist and the plural-form allowlist in `IsTypeKeyword`.
