       # Editor Setup for Flow Language Server

       Flow ships an LSP server (`flow-lsp`) that speaks plain LSP over stdio. Any editor
       with an LSP client can use it. We officially ship a VSCode extension (bundled binary,
       one-click install). For other editors, use one of the snippets here and point the
       editor at a `flow-lsp` binary on your `PATH`.

       ## Getting the binary

       **Option A — Download release tarball (recommended):**
       Pre-built per-platform binaries are at https://github.com/<user>/flow-sharp/releases.
       Extract to a directory on your `PATH`, e.g. `~/.local/bin/`.

       **Option B — Build from source:**
       Requires .NET 10 SDK. From the repo root:
       ```bash
       dotnet publish flow-lsp/flow-lsp.csproj \
         -c Release \
         -r linux-x64 \
         --self-contained \
         -p:PublishSingleFile=true \
         -o ~/.local/bin/flow-lsp-dir
       # then symlink or alias so `flow-lsp` is on PATH
       ```
       Replace `linux-x64` with `win-x64`, `osx-x64`, or `osx-arm64` as appropriate.

       **Critical:** the binary requires the shipped `.flow` stdlib files (`std.flow`,
       `audio.flow`, `collections.flow`, `bars.flow`, `notation.flow`, `composition.flow`)
       to be in the same directory. `dotnet publish` already copies them via the csproj's
       `<CopyToOutputDirectory>` settings — don't move the binary without taking the
       `.flow` files along.

       ## Per-editor configurations

       - [Neovim (nvim-lspconfig)](./nvim-lspconfig.lua)
       - [Helix](./helix-languages.toml)

       Both assume `flow-lsp` is on `PATH`. Open a `.flow` file and the LSP attaches
       automatically.

       ## Not your editor?

       The server speaks standard LSP 3.17 over stdio. See the LSP spec at
       https://microsoft.github.io/language-server-protocol/ for client implementation
       guidance, or consult your editor's LSP-client documentation.

       ## Troubleshooting

       - **"flow-lsp: command not found"** — binary isn't on PATH. Check with `which flow-lsp` (POSIX) / `where.exe flow-lsp` (Windows).
       - **"Flow LSP binary not found at ..."** (VSCode) — the bundled per-platform binary is missing. Try `flow.server.path` setting to point at your own build.
       - **"Definition not found" on `use "@audio"`** — stdlib `.flow` files aren't shipping next to the binary. Re-run `dotnet publish` (the csproj handles this automatically).
       - **No syntax highlighting** (non-VSCode) — most editors' LSP semantic-tokens rendering requires explicit client-side enablement. See your editor's docs; Flow's TextMate grammar is VSCode-specific for now.

       ## Contributing

       Adding editor snippets is welcome. Submit a PR with `docs/editor-setup/<editor>.<ext>`
       following the existing Neovim/Helix examples.
       ```
