    1. **Create `scripts/lsp-smoke.sh`** — sends framed LSP initialize + shutdown + exit to a binary and asserts clean exit under a timeout. Use a small Python helper for LSP framing since bash heredoc + Content-Length math is error-prone:

       ```bash
       #!/usr/bin/env bash
       # scripts/lsp-smoke.sh — Boot-and-shutdown smoke test for flow-lsp binary.
       # Usage: scripts/lsp-smoke.sh <path-to-binary>
       # Exits 0 if the binary responds to initialize and shutdown cleanly within the timeout.
       set -euo pipefail

       BIN="${1:?Usage: lsp-smoke.sh <binary>}"
       TIMEOUT="${LSP_SMOKE_TIMEOUT_SEC:-15}"

       if [[ ! -e "$BIN" ]]; then
         echo "ERROR: binary not found: $BIN" >&2
         exit 2
       fi

       # Ensure executable bit on POSIX (CI downloads may strip it).
       case "$(uname -s)" in
         Linux*|Darwin*) chmod +x "$BIN" 2>/dev/null || true ;;
       esac

       # Python helper handles LSP framing; available on every CI runner (Linux/macOS/Windows Git Bash).
       python3 - "$BIN" "$TIMEOUT" <<'PY'
       import json, os, subprocess, sys, time
       binpath, timeout = sys.argv[1], float(sys.argv[2])

       def frame(obj):
           body = json.dumps(obj).encode('utf-8')
           return f"Content-Length: {len(body)}\r\n\r\n".encode('ascii') + body

       init = {"jsonrpc":"2.0","id":1,"method":"initialize","params":{
           "processId":None,"rootUri":None,"capabilities":{}}}
       shutdown = {"jsonrpc":"2.0","id":2,"method":"shutdown","params":None}
       exit_notif = {"jsonrpc":"2.0","method":"exit"}

       msg = frame(init) + frame(shutdown) + frame(exit_notif)
       p = subprocess.Popen(
           [binpath], stdin=subprocess.PIPE, stdout=subprocess.PIPE, stderr=subprocess.PIPE)
       try:
           out, err = p.communicate(input=msg, timeout=timeout)
       except subprocess.TimeoutExpired:
           p.kill()
           sys.stderr.write("ERROR: binary did not exit within timeout\n")
           sys.stderr.write("partial stderr:\n" + (p.stderr.read() or b'').decode('utf-8', 'replace'))
           sys.exit(3)

       # Accept exit 0 or 1 (some servers exit non-zero on shutdown without initialize-result ack).
       # The test is: binary started, read messages, did not crash or hang.
       if p.returncode not in (0, 1):
           sys.stderr.write(f"ERROR: binary exited with code {p.returncode}\n")
           sys.stderr.write("stderr: " + err.decode('utf-8', 'replace') + "\n")
           sys.exit(p.returncode)

       # Sanity-check stdout contains an LSP initialize response.
       if b"Content-Length" not in out:
           sys.stderr.write("ERROR: no LSP-framed response on stdout\n")
           sys.stderr.write(out.decode('utf-8', 'replace')[:500] + "\n")
           sys.exit(4)

       print("OK: flow-lsp smoke test passed")
       PY
       ```

    ```yaml
    name: Publish Flow Extension
    on:
      push:
        tags: ['v*']
      workflow_dispatch:

    jobs:
      build-server:
        strategy:
          fail-fast: true
          matrix:
            include:
              - rid: linux-x64
                target: linux-x64
                runner: ubuntu-latest
                exe: flow-lsp
              - rid: win-x64
                target: win32-x64
                runner: windows-latest
                exe: flow-lsp.exe
              - rid: osx-x64
                target: darwin-x64
                runner: macos-latest
                exe: flow-lsp
              - rid: osx-arm64
                target: darwin-arm64
                runner: macos-latest
                exe: flow-lsp
        runs-on: ${{ matrix.runner }}
        steps:
          - uses: actions/checkout@v4
          - uses: actions/setup-dotnet@v4
            with:
              dotnet-version: '10.0.x'
          - uses: actions/setup-node@v4
            with:
              node-version: '20'

          - name: Publish flow-lsp (${{ matrix.rid }})
            shell: bash
            run: |
              dotnet publish flow-lsp/flow-lsp.csproj \
                -c Release \
                -r ${{ matrix.rid }} \
                --self-contained \
                -p:PublishSingleFile=true \
                -p:IncludeNativeLibrariesForSelfExtract=true \
                -o vscode-extension/server/${{ matrix.target }}

          - name: Verify stdlib .flow files copied to output (Pitfall 6)
            shell: bash
            run: |
              for f in std.flow audio.flow collections.flow bars.flow notation.flow composition.flow; do
                test -f "vscode-extension/server/${{ matrix.target }}/$f" \
                  || { echo "missing stdlib: $f"; ls -la vscode-extension/server/${{ matrix.target }}/; exit 1; }
              done
              echo "All 6 stdlib .flow files present"

          - name: Smoke-test the binary
            shell: bash
            run: |
              chmod +x scripts/lsp-smoke.sh || true
              bash scripts/lsp-smoke.sh "vscode-extension/server/${{ matrix.target }}/${{ matrix.exe }}"

          - name: Install extension deps
            shell: bash
            working-directory: vscode-extension
            run: npm ci

          - name: Compile TS
            shell: bash
            working-directory: vscode-extension
            run: npx tsc -p .

          - name: Run TM grammar tests
            shell: bash
            working-directory: vscode-extension
            run: npm run test:grammar || echo "WARN: grammar snapshots out of date (plan 17-07 TODO — first-run regeneration)"

          - name: Package VSIX
            shell: bash
            working-directory: vscode-extension
            run: |
              npx vsce package --target ${{ matrix.target }} -o ../flow-${{ matrix.target }}.vsix

          - uses: actions/upload-artifact@v4
            with:
              name: vsix-${{ matrix.target }}
              path: flow-${{ matrix.target }}.vsix

      publish:
        needs: build-server
        runs-on: ubuntu-latest
        if: startsWith(github.ref, 'refs/tags/v')
        strategy:
          fail-fast: false
          matrix:
            target: [linux-x64, win32-x64, darwin-x64, darwin-arm64]
        steps:
          - uses: actions/download-artifact@v4
            with:
              name: vsix-${{ matrix.target }}
              path: artifacts

          - name: Publish to VSCode Marketplace (${{ matrix.target }})
            uses: HaaLeo/publish-vscode-extension@v2
            with:
              pat: ${{ secrets.VSCE_PAT }}
              extensionFile: artifacts/flow-${{ matrix.target }}.vsix
              registryUrl: https://marketplace.visualstudio.com

          - name: Publish to OpenVSX (${{ matrix.target }})
            uses: HaaLeo/publish-vscode-extension@v2
            with:
              pat: ${{ secrets.OVSX_PAT }}
              extensionFile: artifacts/flow-${{ matrix.target }}.vsix
    ```

    **Matrix design rationale:**
    - `build-server` job matrix has 4 rows — one per platform — each building + smoke-testing + packaging. Runs on push to any branch via workflow_dispatch, but only publishes on tag.
    - `publish` job depends on build-server completing, downloads all 4 VSIXs, then loops over the 4 targets via its own matrix to publish each to both Marketplace and OpenVSX (8 publish operations total per tag).
    - `fail-fast: false` on the publish job means if Marketplace fails for darwin-arm64 but linux-x64 succeeded, linux is still live and darwin-arm64 can be re-tried manually. Build-server keeps `fail-fast: true` — if any platform can't build, don't proceed to publish.

    **Secrets required (documented in plan 17-08's one-time setup checklist):**
    - `VSCE_PAT` — Azure DevOps Personal Access Token with `Marketplace (Publish)` scope
    - `OVSX_PAT` — Eclipse Open VSX Personal Access Token
    - OpenVSX namespace must be claimed once via `npx ovsx create-namespace <publisher>` before first tag push (Pitfall 8) — plan 17-08 concern.

    **Verification notes:**
    - Do NOT try to run the workflow from this plan — it requires a tag push. Syntactic validation via `yamllint` (if available) or GitHub's own `gh workflow view` after commit is enough. The real test is the first tag push, which plan 17-08 coordinates.
    - Workflow syntax error at commit time would show up in the GitHub Actions UI as "Invalid workflow file" — safe to catch post-commit, before first tag.

    If `yamllint` or `gh workflow lint` is available locally, run it. Otherwise, the acceptance criterion is a file-existence + basic structural grep.
