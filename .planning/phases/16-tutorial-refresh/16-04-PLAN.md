SUGGESTED SKELETON (executor may revise musical content):
```flow
use "@std"
use "@audio"
use "@composition"

(print "Flow Showcase — v1.2 Ambient Piece")
(print "Generating examples/output/flow_showcase.{wav,mid} ...")

tempo 80 {
    timesig 4/4 {
        key Aminor {
            // Soft pad with crescendo — sets the bed
            Sequence pad = | A3w | E4w | C4w | A3w |
            Sequence padCresc = pad -> crescendo 0.2 0.55

            // Euclidean groove — sparse, humanized, fixed seed for reproducibility
            Sequence groove = (euclidean 5 16 A2 0.2 0.15 7)

            // Soft melody on top
            dynamics mp {
                Sequence mel = | _ _ E5q G5q | A5h E5h | _ _ G5q A5q | E5w |
            }

            // Wrap the whole thing in a long reverb tail
            reverbTime 3.0 {
                section atmosphere {
                    Sequence pp = padCresc
                    Sequence gg = groove
                    Sequence mm = | _ _ E5q G5q | A5h E5h | _ _ G5q A5q | E5w |
                }
                Song showcase = [atmosphere]

                Buffer rendered = (renderSong showcase "strings")
                Double negSix = (sub 0.0 6.0)
                Buffer finalMix = rendered -> (lowpass 3000.0) -> (gain negSix)

                (writeWav "examples/output/flow_showcase.wav" finalMix)
                (writeMidi "examples/output/flow_showcase.mid" showcase)
            }
        }
    }
}

(print "WAV:  examples/output/flow_showcase.wav")
(print "MIDI: examples/output/flow_showcase.mid")
```

KNOWN CONSTRAINTS / KNOWN ISSUES:
- `dynamics mp { ... }` inside a section declaration: the dynamics block typically wraps a sequence or a section, not a Sequence inside a section's body. The skeleton above puts `dynamics mp` AROUND a `Sequence mel = | ... |` declaration outside any section; this declares mel with mp velocity and then mel can be used inside a section. Confirm by checking tests/test_dynamics.flow — line 26 shows `dynamics f { Sequence forteMel = | ... | (print (str forteMel)) }` so dynamics CAN wrap a sequence declaration. OK.
- `dynamics mp` — `mp` is a recognized dynamics marking. tests/test_dynamics.flow line 12 uses `pp`. Per Phase 14 D-08: dynamics ff/f/mf/mp/p/pp are all parsed. The block form sets a base velocity for the body.
- A section can contain multiple Sequence variables; they layer (per existing graduation piece).
- A section inside reverbTime: yes — tests/test_reverb_time.flow line 8-15 shows `reverbTime 2.5 { Sequence a = | ... | section hall { a } Song s1 = [hall] Buffer b = (renderSong s1 "piano") }`. Sequence and section declarations BOTH happen inside the reverbTime block. The Song is constructed inside the block too.
- Multi-section vs multi-Sequence-in-section: the existing graduation has both. For showcase, fewer sections is fine.
- renderSong's 2nd arg can be "strings" (Phase 8 v1.1 preset). Other valid: "piano", "organ", "bell", "brass", "sax", "drums". For ambient, "strings" or "organ" sound best. Executor's call.

CHARITABLE INTERPRETATION D-16: choose key + tempo + structure that sounds GOOD with default settings. If something sounds harsh on first listen (the executor should run the showcase and listen if possible), change it. The showcase's reputation depends on it sounding pleasant.

NEGATIVE-DOUBLE IDIOM D-17: `(sub 0.0 N)` for negative double literals. Used in skeleton for `negSix = (sub 0.0 6.0)`.
