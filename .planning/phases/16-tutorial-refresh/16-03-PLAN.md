Per CONTEXT D-07, the 4 features that MUST be integrated audibly are:
1. reverbTime — wrap a section in `reverbTime N { ... }` for a hearable RT60 tail
2. euclidean swing + humanize — drum or bass groove using the 6-arg overload with fixed seed
3. per-section gain — vary section loudness via `gain N { section ... }` wrapping
4. tempoRamp — ritardando or accelerando moment somewhere in the song

How features compose with the existing structure:
- gain context block wraps a section declaration: `gain 0.6 { section quietPart { ... } }` — the section's `Gain` field gets set on the rendered voice. SongRenderer reads section.Gain in its voice loop.
- reverbTime context block wraps a section similarly: `reverbTime 2.0 { section hall { ... } }` — section.ReverbTime gets set; SongRenderer per-voice reverb fires with that RT60 (Phase 15 Plan 03).
- THESE TWO CAN BE NESTED. Per Phase 15 F-05 (Nested_WithGain_Independent), gain and reverbTime stack independently when nested in a single section's context.
- euclidean produces a Sequence value. To use it in a section, declare the section and put the euclidean call as the Sequence: `section drumGroove { Sequence drums = (euclidean 5 16 C3 0.2 0.1 42) }` or use it as a bare expression inside the section if the parser supports that.
- tempoRamp produces a Buffer (NOT a Sequence). It's NOT something you put inside a section. It produces a stand-alone Buffer that has to be MIXED with the renderSong output, OR rendered separately and concatenated/layered. The cleanest tutorial-level integration is: render a small bridge or transitional Sequence with tempoRamp, mix it with a portion of the song's existing render. See INTEGRATION STRATEGY below.

INTEGRATION STRATEGY (planner's call per CONTEXT §Claude's Discretion — "Exact musical content of the graduation piece (key, tempo, structure, number of sections) as long as the 4 audible features (D-07) are integrated"):

Plan A (RECOMMENDED — minimum-churn, musically natural):
1. Wrap `sunriseIntro` in `gain 0.6 { ... }` — quiet intro per dynamic arc.
2. Wrap `sunriseChorus` in `gain 1.0 { ... }` (explicit normal-gain wrap is fine — visible structure).
3. Wrap `sunriseOutro` in `reverbTime 2.5 { ... }` for a hall-tail outro.
4. Add a NEW section `sunriseGroove` containing a euclidean drum-like Sequence:
   `section sunriseGroove { Sequence drums = (euclidean 5 16 C3 0.2 0.1 42) }`
   Place it once in the Song arrangement (e.g., between intro and verse, or alongside chorus):
   `Song sunrise = [sunriseIntro sunriseGroove sunriseVerse*2 sunriseChorus sunriseVerse sunriseChorus sunriseOutro]`
5. Add a tempoRamp Buffer rendered separately and mixed into the final mix:
   ```
   Sequence tail = | C4h G3h C3w |
   Buffer ritBuf = (tempoRamp tail 100.0 60.0)         // ritardando ending
   Buffer finalMix = rawMix -> (reverb 0.25) -> (lowpass 4000.0) -> (gain negTwo)
   Buffer finalWithTail = (mix finalMix ritBuf)
   ```
   Then writeWav writes finalWithTail. (writeMidi still writes `sunrise` which doesn't include the tempoRamp tail — the MIDI captures the song structure, the WAV adds the audible ritardando.)

   Per CONTEXT D-07, tempoRamp is one of the 4 audible features. The mix-in approach is the cleanest tutorial integration; the alternative (re-rendering a section through tempoRamp) requires more glue. Note that the WAV and MIDI will not match perfectly — the WAV has the audible ritardando tail; the MIDI captures the song notation only. This is fine and DOCUMENT IT in a `Note:` comment so the reader understands the asymmetry: "Note: tempoRamp produces a Buffer; we mix it onto the WAV but not the MIDI (MIDI captures notation, not realized timing)."

Plan B (alternative — only if Plan A's mix-in feels awkward):
Render the WHOLE song through tempoRamp by giving each section a ritardando-shaped voice. This requires per-section tempo-aware rendering and is significantly more complex. NOT RECOMMENDED.

KNOWN PARSER QUIRKS:
- Section variable scoping: each section gets its own scope. Sequence variables don't leak across sections.
- Negative-double idiom (`(sub 0.0 N)`) — already used in graduation for `negTwo`. Reuse.
- gain context value can be Double (gain 0.6) or Int (gain 1) — both parse. Use Double for explicit clarity.
- reverbTime takes a Double in seconds; positive values clamp at 30s; negative parse-error; 0 = dry sentinel.
- The euclidean argument order (per shipped tests) is `(euclidean steps hits note swing humanize seed)`. CONFIRM by reading tests/test_euclidean_swing.flow before authoring this section: line 8 has `(euclidean 3 8 C4 0.3)` and the comment above line 7 says "3 hits over 8 steps". So the FIRST integer literal in the call is "3" matching the description's "3 hits"; tests/test_euclidean_humanize.flow line 13 mirrors this: `(euclidean 3 8 C4 0.3 0.1 42)`. Per Phase 15 SUMMARY: "euclidean(hits, steps, note, swing) and euclidean(hits, steps, note, swing, humanize, seed) overloads". So the order IS (hits, steps, note, swing[, humanize, seed]). This plan's snippet uses 5 hits over 16 steps for a denser groove — confirm with `(euclidean 5 16 C3 0.2 0.1 42)`.

GROOVE SECTION CAVEAT: A single euclidean call on C3 produces a Sequence of mostly-C3 hits. When rendered through "piano", this sounds like a percussive low-piano groove — adequate for tutorial purposes. If rendering through "drums" feels more rhythm-section-appropriate, change `(renderSong sunrise "piano")` to a per-section instrument override. PLAN: keep "piano" for simplicity (the existing tutorial uses "piano"); the groove section will sound like piano staccato low notes. Charitable interpretation D-16: music > rigid correctness — the tutorial is teaching, not making a hit record.

TEMPO RAMP TAIL TIMING: tempoRamp(seq, 100, 60) on a 4-bar tail Sequence at 4/4 produces a Buffer that's ~6-8 seconds (slowing down extends the duration). When mixed onto finalMix (which is the full 6-section song, ~30-40 seconds), the ritardando tail mixes onto the whole song from frame 0. Per tests/test_mix.flow this is fine — mix sums sample-by-sample with mono→stereo promotion if needed. The result: the ritardando is audible UNDER the song from the very start, with the song fading out before the ritardando does. ALTERNATIVE: render the ritardando tail and concatenate it AFTER finalMix. There is no built-in `concat` for Buffers in the stdlib (per spot-check; mix is the only buffer-combiner in audio.flow). Since tutorial purpose is DEMONSTRATION not perfection, the mix-from-frame-0 approach is acceptable. Per CONTEXT D-16 (charitable interpretation): document the asymmetry in a comment and move on.
