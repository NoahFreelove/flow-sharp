<interfaces>
Naming conventions for music-domain builtins (consult existing C# `args[N].As<X>()` variable names + Phase 26.2 ERG locked decisions):

Effects + DSP:
- `compress(Buffer, Decibel|Double, Double, Millisecond|Double, Millisecond|Double)`: names `buf, threshold, ratio, attack, release`
- `sidechain(Buffer, Buffer, Decibel|Double, Double, Ms|Double, Ms|Double)`: names `buf, sidechain, threshold, ratio, attack, release`
- `reverb(Buffer, Double, Second|Double)`: names `buf, wet, decay` (or `room` — pick the existing C# local; see existing source)
- `delay(Buffer, Millisecond|Double, Double, Double)`: names `buf, timeMs, feedback, mix`
- `lowpass(Buffer, Hertz|Double)`: names `buf, cutoff`
- `highpass(Buffer, Hertz|Double)`: names `buf, cutoff`
- `bandpass(Buffer, Hertz, Hertz)`: names `buf, low, high`
- `gain(Buffer, Decibel|Double)`: names `buf, db`
- `volume(Buffer, Double)`: names `buf, factor`

Signal generation:
- `createSineTone(Double, Hertz|Double, Double)`: names `duration, freq, amplitude`
- Same for `createSawTone` / `createSquareTone` / `createTriangleTone`

Transforms (TransformFunctions.cs):
- `transpose(Sequence, Semitone|Int|Cent)`: names `seq, amount`
- `invert(Sequence, Note)`: names `seq, axis`
- `retrograde(Sequence)`: name `seq`
- `augment(Sequence, Int|Double)`: names `seq, factor`
- `diminish(Sequence, Int|Double)`: names `seq, factor`
- `up(Sequence)` / `down(Sequence)`: name `seq`
- `repeat(Sequence, Int)`: names `seq, times`
- `legato(Sequence, Double)`: names `seq, overlap`
- `portamento(Sequence, Millisecond)`: names `seq, glideMs`
- `quantize(Sequence, NoteValue, Double, Double)`: names `seq, resolution, strength, swing`

Harmony (HarmonyFunctions.cs RegisterContextDependent shape preserved):
- `enharmonic(Note)`: name `note`
- `chordNotes(Chord)`: name `chord`
- `arpeggio(Chord, NoteValue, String, String)`: names `chord, rate, direction, pattern`
- `inversion(Chord, Int)`: names `chord, n`
- `voicing(Chord, String)`: names `chord, voicing`
- `scaleNotes(String|Key)`: name `scale` or `key` per existing var
- `resolveNumeral(String)`: name `numeral`

Composition (VariationFunctions.cs etc.):
- `vary(Sequence, Double, [Int seed])`: names `seq, probability, seed`
- `humanize(Sequence, Double, Int)`: names `seq, amount, seed`
- `humanizeGaussian(Sequence, Double, Int)`: same shape
- `euclidean(Int, Int, Double)`: names `pulses, steps, ?` (use existing locals)

Tuning + SFZ (Phase 32/33 — single-arg loaders):
- `loadScala(String)`: name `path`
- `loadScala(String, String)`: names `sclPath, kbmPath`
- `loadSfz(Symbol)`: name `instrument`
- `loadSfz(String)`: name `path`

Test framework (TestFunctions.cs):
- `test(String, Lazy)`: names `name, body`
- `assert(Bool)`: name `cond`
- `assertEq(Value, Value)`: names `actual, expected`
- `assertNotesMatch(Sequence, Sequence)`: names `a, b`
- `assertBytesEqual(Buffer, Buffer)`: names `a, b`
- `assertWithinDb(Buffer, Buffer, Decibel)`: names `a, b, tolerance`

NOTE: many Harmony / Audio / Composition registrations use `RegisterContextDependent(registry, context)` shape instead of `Register(registry)`. The pattern for adding ParameterNames is identical — the registration call still constructs a FunctionSignature, so the ParameterNames addition applies the same way.
