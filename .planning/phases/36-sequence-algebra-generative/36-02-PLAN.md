<objective>
Ship the language-foundation overlap of Phase 36 (D-36-11): universal named-argument call syntax `(fn name1=val1 name2=val2)`. This plan delivers ONLY the syntax + resolver — backfilling the ~350 existing builtin signatures with parameter names happens in parallel Plans 36-03 + 36-04 in Wave 3. Critical safety net: signatures without `ParameterNames` still resolve via the existing positional path, so the backfill plans can ship in parallel without breaking anything.

Purpose: Composer surface `(jam over=chords style=#jazz length=8)` (D-36-10) requires named-arg syntax. The Markov feature-extraction surface `(markov corpus order length seed features=#pitch)` (D-36-07) requires it. Section calls with defaulted params require it (D-36-15). The whole-language rollout is the right scope per D-36-11 — incremental adoption is cleaner than a Phase 36-only carve-out.

Output: FunctionSignature.ParameterNames defaulted field; FunctionCallExpression.NamedArgs defaulted field; Parser argument-list extension; OverloadResolver named-arg dispatch; xUnit facts; composer-facing test.
</objective>
