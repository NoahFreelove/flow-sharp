# Phase 38 — UI Design Contract

> Visual and interaction contract for Phase 38 (Live Coding 2.0). This phase is **entirely TERMINAL-RENDERED** — there is no web/mobile/Electron frontend. The web-flavored sections of the standard UI-SPEC template are reinterpreted below for terminal surfaces. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Composer ergonomics first** (CLAUDE.md Goal #1) — every choice below biases toward fewer keystrokes / less eye-tracking for the composer mid-session.

Phase 38 has four user-facing terminal surfaces:

| # | Surface | Lives in | REQs |
|---|---------|----------|------|
| 1 | **ANSI live status panel** (4-row, redraws in place in `flow watch`) | `flow-interpreter/LiveReloadManager.cs` rewrite (Plan 38-01) | LIVE-02 |

## Spacing Scale (Terminal Adaptation)

Terminal spacing is measured in **monospace character cells**, not pixels. The "spacing scale" defines column gutters and row spacing inside the ANSI status panel and the piano-roll.

| Token | Cells | Usage |
|-------|-------|-------|
| inline-gap | 1 cell | Single space between fields on a status row (e.g. `Tempo: 120` ␣ `|` ␣ `Bar: 47`) |
| field-gap | 3 cells | Visual separator between top-level fields on the status row (` | ` with surrounding spaces) |
| label-gutter | 4–6 cells | Left margin in the piano-roll holding pitch labels (`F#5 |…`); auto-widened to the longest label per existing `VisualizationFunctions` logic |
| panel-leading | 0 rows | Status panel starts at terminal row 1 (no leading blank rows — terminal real estate is precious) |
| panel-trailing | 1 blank row | One blank row below the panel before normal stdout/stderr output resumes |
| roll-row-stride | 1 row per semitone | Piano-roll row stride — one terminal row = one MIDI semitone (existing) |
| roll-col-per-beat | 2 columns per beat | Piano-roll horizontal resolution = eighth-note (existing — preserved per Pitfall #13 readability target) |

**Exceptions:**
- Tick-mark row (Plan 38-04 extension) adds 1 row above the first pitch row of the piano-roll, holding bar numbers + downbeat ticks (`1     2     3     4    `).
- Sticky advisory row (panel row 4) auto-clears its content after 8 seconds (D-38-08 Claude's discretion default — researcher confirms at plan time).

## Typography (Terminal Adaptation)

Terminal "typography" is the choice of **ANSI text attributes** (bold / dim / reverse / underline). The composer's terminal font determines pixel size; we declare semantic roles.

| Role | ANSI attribute | Usage | Notes |
|------|----------------|-------|-------|
| Body | none (default weight) | Status panel field values, REPL prompt, piano-roll grid | Default terminal weight |
| Label | **dim** (`ESC[2m`) | Status panel field labels (`Tempo:`, `Bar:`, `Voices:`), piano-roll pitch labels | Dim labels let values pop visually |
| Emphasis | **bold** (`ESC[1m`) | Current bar number when at-boundary; just-swapped `live` block name (1 redraw cycle); active prompt `>` | Reserved for transient highlights; never decorative |
| Inverse | **reverse video** (`ESC[7m`) | NOT USED in v1.5 (reserved for v1.6 selection / highlighting in REPL line editor if `PrettyPrompt` ships) | Documented to prevent ad-hoc use |

**Hard limits (consistent with web template's "3-4 sizes / 2 weights" rule, terminal-adapted):**
- Exactly **3 attribute roles** in use: default, dim, bold. Reverse held in reserve.
- Composer can disable all attributes via `--no-color` flag OR `NO_COLOR` env var (per industry convention, https://no-color.org).

## Color (ANSI Palette)

Terminal color is **ANSI 16-color baseline** (foreground only — no background colors used; preserves composer's terminal theme). The 60/30/10 split from the web template is adapted to "dominant role / secondary role / accent reserved-for".

| Role | ANSI color | Usage |
|------|-----------|-------|
| **Dominant (60%)** — default text | `default` (no escape) | All steady-state text: piano-roll grid, status panel field values, REPL output, normal stdout |
| **Secondary (30%)** — informational | `cyan` (`ESC[36m`) | Status panel labels when terminal supports color; "Reloaded at bar N" success line; piano-roll bar-tick row labels |
| **Accent (10%)** — attention | `green` (`ESC[32m`) | `live` block swap event line ("Live block at L12 swapped at bar 47"); successful `:help fn` header (proc name line) |
| **Destructive** | `red` (`ESC[31m`) | Parse errors, runtime errors, `[live] timeout`, `[live] stale closure` advisories, `[osc] bind failed` |
| **Advisory** | `yellow` (`ESC[33m`) | Non-fatal `[live]` / `[osc]` / `[audio-in]` advisories that opt OUT of determinism or recover charitably (e.g. file-scope edit detected, OSC type-tag coercion fallback) |

**Accent (green) reserved for** — explicit list, never "all interactive elements":
1. `live` block successful hot-swap event (per-block, 1 redraw cycle)
2. `:help fn` proc-name header line
3. `(inspect seq)` "rendering N bars / M notes" summary line above the grid

**Why this palette holds up:**
- All 5 colors are in the ANSI 8-color baseline (no 256-color requirement) — works on `dumb`, `xterm`, `xterm-256color`, `vt100`, Windows Terminal, iTerm2, gnome-terminal, Konsole.
- Composer's terminal theme controls actual rendering (`xterm` default cyan looks different in Solarized Dark vs Gruvbox — that's correct, we don't override).
- `--no-color` and `NO_COLOR=1` disable ALL escapes; the panel still works (just monochrome).

**Color-disable detection (locked):**
```
isColorEnabled = !Environment.GetEnvironmentVariable("NO_COLOR")
              && !cliArgs.Contains("--no-color")
              && !Console.IsOutputRedirected
              && Environment.GetEnvironmentVariable("TERM") != "dumb"
```

## ANSI Live Status Panel (D-38-08 Specification)

The modernized `flow watch` redraws this 4-row panel in place at the top of the terminal. Plain-line fallback (per `Console.IsOutputRedirected`) emits the same rows once per state change with no cursor-move escapes.

### Panel Layout

```
Row 1: Tempo: 120 BPM | TimeSig: 4/4 | Bar: 47
Row 2: Live blocks: live 1bar @ L12 (last swap bar 47, 32s ago) | live 2bar @ L34 (last swap bar 46, 1m4s ago)
Row 3: Voices: 8/32 | piano:3 brass:2 strings:3
Row 4: [live] last advisory line — auto-cleared after 8s
```

### Cell Contract (per row)

**Row 1 — Musical context:**
- Field order is locked: `Tempo` → `TimeSig` → `Bar`. Composer-stable scan position.
- `Tempo` reads from active `MusicalContext.Tempo`; format `N.N BPM` (1 decimal if non-integer, else integer).
- `TimeSig` reads from active `MusicalContext.TimeSignature`; format `N/M`.
- `Bar` reads from `LiveReloadManager` position counter; format integer, 1-indexed (matches existing `Reloaded at bar {N}` semantics).
- All labels dim per Typography table.

**Row 2 — Live blocks (collapses if zero blocks):**
- Omit row entirely when no `live { }` blocks exist in the file (whole-script swap mode per D-38-01). The panel shrinks to 3 rows.
- Multiple blocks separated by `field-gap` (` | `).
- Each block shows: `live <quantize> @ L<line>` + parenthesized `(last swap bar N, Xs ago)`.
- "X ago" format: `<60s` → `Ns`, `<60m` → `NmNs`, `≥60m` → `NhNmNs`.
- Just-swapped block (within 1 second of swap event) renders the block-name segment **bold** + green for 1 redraw cycle.

**Row 3 — Voice pool:**
- `Voices: N/M` where M is the locked Phase 28 default 32 (per `VoiceAllocator.SPEC-7`).
- Per-instrument breakdown: `instrument:count` pairs separated by inline-gap.
- Instrument order: descending count; tie-break by instrument-name alphabetical (deterministic per Phase 28 voice-allocator precedent).

**Row 4 — Sticky advisory (auto-clears):**
- Holds the most recent `[live]` / `[osc]` / `[audio-in]` / `[error]` stderr line.
- Cleared after 8 seconds OR replaced by a newer advisory, whichever comes first.
- Rendered in **yellow** for advisory class, **red** for error class (per Color table).
- Empty state (no recent advisory): row 4 shows empty `[ ]` placeholder ONLY when a previous advisory has been cleared. Cold-start: row 4 omitted until first advisory.

### Redraw Cadence

| Trigger | Cadence | Notes |
|---------|---------|-------|
| Bar-boundary crossed | Event-driven | Row 1 `Bar:` increments; row 3 voice count may shift |
| Live block swapped | Event-driven | Row 2 "last swap bar / ago" updates; flash green+bold for 1 cycle |
| Advisory emitted | Event-driven | Row 4 swaps to new message |
| "ago" timer tick | **2 Hz** (every 500ms) | Updates the "(...s ago)" suffix in row 2 + the 8s sticky-advisory clear timer |
| Tempo/Timesig change inside `live` block | Event-driven | Row 1 fields update at next bar boundary swap (matches Phase 28 musical-context apply-at-bar-boundary rule) |

**Note on 2 Hz cap:** Pitfall #21 emphasizes 200ms file-watch debounce and never blocking the audio thread. The 2 Hz redraw cap keeps the panel rendering off the hot path; redraws happen on a dedicated `Task.Run` thread with a `Timer(500ms)` heartbeat that calls `RedrawPanel()` only if state changed since last redraw.

### TTY-Detection Fallback (locked)

When `Console.IsOutputRedirected == true` OR `TERM == "dumb"` OR `--no-color` flag set:
- No ANSI cursor moves emitted (no panel redraw — would garble pipes / CI logs).
- Each state change emits a plain line: `[watch] tempo=120 timesig=4/4 bar=47 voices=8/32`, `[watch] live block @L12 swapped at bar 47`, etc.
- Advisory lines (`[live] …`) emit identically in both modes (already plain-text by convention).

## ASCII Piano-Roll (D-38-10 Extension Spec)

The existing `(visualize seq)` builtin (`flow-lang/StandardLibrary/VisualizationFunctions.cs`) is extended per D-38-10 with **articulation glyphs at note onsets** and **sharper bar tick marks**. `(inspect seq)` ships as a builtin-level alias backed by the same renderer.

### Glyph Inventory (LOCKED — ASCII-only, no Unicode)

| Glyph | Cell | Meaning | Phase 28 source |
|-------|------|---------|-----------------|
| `#` | 1 | Sustained note body (existing — unchanged from current renderer) | n/a |
| `>` | 1 | Accent at note onset | `Articulation.Accent` |
| `.` | 1 | Staccato at note onset | `Articulation.Staccato` |
| `^` | 1 | Marcato at note onset | `Articulation.Marcato` |
| `_` | 1 | Tenuto at note onset | `Articulation.Tenuto` |
| `!` | 1 | Sforzando at note onset | `Articulation.Sforzando` |
| `~` | 1 | Legato — drawn as an overline cell BETWEEN connected notes (interior of slur span) | `Articulation.Legato` |
| (no glyph) | 1 | `Articulation.Normal` — note starts with `#` directly, no onset marker | default |
| `|` | 1 | Bar line (existing — unchanged) | n/a |
| `+` | 1 | Tick mark + bar number intersection on the new tick-mark row (Plan 38-04 addition) | n/a |
| `-` | 1 | Tick-mark row horizontal rule between bar numbers | n/a |

**Why ASCII-only (locked):**
- Unicode box-drawing or musical symbols (`♩`, `𝅗𝅥`) break in `xterm` / `vt100` / `dumb` / older Windows consoles. Pitfall #21 implies these terminals matter.
- All Phase 28 articulations have single-cell ASCII equivalents that overload to existing music notation conventions (`>` = accent in Helmholtz, `.` = staccato dot, `^` = marcato wedge, `_` = tenuto bar).
- Composer ergonomics: ASCII-only is grep-able, copy-pasteable into commit messages and README snippets without encoding hazards.

### Glyph Composition Rules

- **Onset cell:** When a note has a non-`Normal` articulation, the FIRST cell of the note's sustained-body region is the articulation glyph; subsequent cells are `#`. Example: an accented half-note at beat 1 in a 4-beat bar at `columnsPerBeat=2` renders as `>###` (7 cells: onset glyph + 3 sustain cells).
- **Single-cell note:** When a note's duration < 1 column, the cell is the articulation glyph alone (no `#` follows). Example: a staccato sixteenth note in a `columnsPerBeat=2` grid is `.` only.
- **Legato (`~`):** Drawn in the gap-cell BETWEEN two connected notes (NOT at the onset of either). Example: a slur connecting C4 and D4, each a quarter at `columnsPerBeat=2`, renders as `##~##` on the D4's row — the `~` overrides the empty cell that would otherwise sit between them. If notes are non-adjacent in pitch, the `~` renders on the LATER note's row.
- **Collision with `#`:** Onset glyph always wins over a sustain `#` (it's the same cell — the onset is the start of the note).
- **Collision with bar line `|`:** Bar line wins (preserve bar-line visibility — pitfall #13 readability target).

### Tick-Mark Row (Plan 38-04 addition)

A new row is rendered ABOVE the first pitch row of the existing piano-roll. Format:

```
    +----+----+----+----+
       1    2    3    4
F#5 |    >####|        |    (existing pitch rows below, unchanged structure)
```

- Bar numbers (`1`, `2`, …) sit at the column of each bar's first beat.
- `+` glyph at each bar-line column, `-` glyph at all other columns of the tick row.
- Beat numbers (`1`, `2`, `3`, `4` within a 4/4 bar) sit BELOW the existing bottom separator (already present in `VisualizeBuffer`'s existing logic — preserved unchanged).

### Backwards Compatibility

- `(visualize seq)` continues to render correctly for all existing scripts in `tests/` and `examples/`. New articulation glyphs only appear when the sequence carries Phase 28 articulation data (which is mostly inert pre-existing tests).
- `(inspect seq)` is a NEW name — composer can call either; identical output.
- `(visualize buf)` (waveform variant) is unchanged in this phase.

### `:help fn` Meta-Command (D-38-09 — overrides REQUIREMENTS.md REPL-02 `?fn` wording)

`:help` (bare) — shows the existing REPL help text (preserved from `Repl.cs:229-256`).

`:help <name>` — looks up `<name>` in `BuiltInDocs._docs` via `TryGet(identifier)` and prints:

```
:help transpose

transpose                                         ← bold + green header line
  (transpose Sequence interval) → Sequence        ← dim signature line
  (transpose Sequence cents=Cent) → Sequence

  Shifts every note in a Sequence by the given    ← body of doc-comment (default text)
  semitone interval or cent offset. Negative
  intervals shift down.

  Example:                                        ← dim "Example:" label
    | C4 E4 G4 | -> (transpose 5)
    -- becomes -- | F4 A4 C5 |                    ← default text
```

- Header: proc-name only, **bold + green** (matches Color accent reserved-for #2).
- Signature: **dim** (low visual weight; reference material).
- Body: default attribute (primary reading).
- Example: 1-line example pulled from `BuiltInDocs` entry; rendered with `--` comment-style annotation when the entry includes a `--` comment.

**Unknown identifier:**
```
:help fooBar
[help] no documentation entry for 'fooBar' — try ':help' for the meta-command list
```
- Yellow (advisory color); does NOT spam stderr (REPL stdout only — composer is interactively asking).

## Structured Stderr Advisory Format (LOCKED)

All Phase 38 advisories follow the existing Flow `[prefix] body` pattern established by `[tuning]` / `[abc]` / `[mml]` precedents.

### Format Contract

```
[<surface>] <message body> [at line <N>] [— <recovery action>]
```

- `<surface>` ∈ `{live, osc, audio-in, watch, error, help}`
- `<message body>` — one sentence, lowercase first word (consistent with Flow's existing advisory style at `flow-lang/Diagnostics/RenderingDiagnostics.cs`)
- `[at line <N>]` — optional source location when applicable
- `[— <recovery action>]` — em-dash + recovery sentence when the composer can act on it (e.g. "keeping previous version", "restart `flow watch` to apply")

### Advisory Catalog (CTA / Empty / Error / Recovery — terminal-adapted)

| Element | Copy | Color | Dedup key |
|---------|------|-------|-----------|
| **Primary CTA** (LIVE-01) | (no explicit CTA — `live { … }` block IS the action; composer-facing tutorial in `examples/live/hello_live.flow`) | n/a | n/a |
| **Empty state — REPL `:help fn` unknown** | `[help] no documentation entry for '<name>' — try ':help' for the meta-command list` | yellow | none (composer-interactive) |
| **Empty state — `(inspect <empty>)`** | `(empty sequence)` (preserved from existing `VisualizationFunctions.cs:39`) | default | none |
| **Empty state — `(inspect <empty bar>)`** | `(no notes in sequence)` (preserved from `VisualizationFunctions.cs:83`) | default | none |
| **Live block successful swap** | `[live] block @L<N> swapped at bar <M>` | green | none (event) |
| **Live block timeout** (D-38-07) | `[live] evaluation timed out at 30s at line <N> — keeping previous version` | red | `live-timeout:<line>` |
| **Live block stale closure** (D-38-07) | `[live] stale closure: references removed binding '<name>' at line <N> — keeping previous version` | red | `live-stale-closure:<name>:<line>` |
| **Live block parse error** | `[live] <error message> at line <N> — keeping previous version` | red | `live-parse:<line>` |
| **Live determinism opt-out** (D-v1.5-07) | `[live] entering live block at line <N> — opts OUT of two-run cmp-clean determinism` | yellow | `live-determinism-optout:<line>` (one-shot per live block per process) |
| **File-scope edit detected outside live blocks** (D-38-04) | `[live] file-scope edit detected outside live blocks at line <N> — restart 'flow watch' to apply` | yellow | `live-fscope-edit:<filepath>:<line>` |
| **Audio-input feedback guard** (Pitfall #24) | `[audio-in] mic stream attenuated -20 dB on open to prevent feedback` | yellow | `audio-in-attenuate:open` (one-shot per `micBuffer` call) |
| **Audio-input sample-rate mismatch** | `[audio-in] resampling capture stream from <N> Hz to 44100 Hz (linear interpolation)` | yellow | `audio-in-resample:<N>` |
| **OSC bind failure** | `[osc] bind failed on port <N> — port already in use; oscListen returned no handle` | red | `osc-bind:<port>` |
| **OSC type-tag inference fallback** (D-38-13) | `[osc] type-tag inferred as '<tag>' for arg <i> at <path> — pass an explicit cast for finer control` | yellow | `osc-infer:<path>:<arg-index>` (one-shot per path per process) |
| **OSC bundle depth exceeded** (D-38-15) | `[osc] bundle nesting depth exceeds 8 at <path> — collapsing to flat dispatch` | yellow | `osc-bundle-depth:<path>` |
| **OSC rate-limit dropped (default: silent per D-38-14)** | (no advisory by default; researcher decides at Plan 38-06 whether to surface a one-shot `[osc] /<path>: flood detected (rate-limit active)`) | yellow if enabled | `osc-flood:<path>` |
| **Destructive — `:quit` from REPL with active audio** | (no explicit confirmation; Ctrl+C semantics already lock to "stop audio without exiting"; `:quit` exits unconditionally per preserved `Repl.cs:214`) | default | n/a |

### Color/Severity Discipline

- **red** = error class — composer must investigate; advisory carries a recovery sentence
- **yellow** = advisory class — recovery already happened charitably; composer is informed not alerted
- **green** = success event — `live` swap, `:help` header
- **default** = informational — empty state, normal output

The web template's copywriting contract is reinterpreted for terminal surfaces.

| Element | Copy |

| **Empty state — `(inspect emptySeq)`** | `(empty sequence)` |
| **Empty state — `:help` (no arg)** | (existing REPL help text — preserved unchanged from `Repl.cs:231-255`; appended one line: `  :help <name>     - Show docs for a builtin (e.g. ':help transpose')`) |
| **Error state — live block timeout** | `[live] evaluation timed out at 30s at line N — keeping previous version` |
| **Error state — REPL parse failure** | (existing Rust-style multi-line diagnostic via Phase 35-03 DiagnosticRenderer — preserved unchanged from `Repl.cs:69-71`) |
| **Error state — OSC bind failure** | `[osc] bind failed on port <N> — port already in use; oscListen returned no handle` |
| **Destructive confirmation** | NONE in Phase 38. The only destructive composer actions are `Ctrl+C` (stops audio, preserves session) and `:quit` (exits REPL); both are explicitly composer-initiated single keystrokes / single commands and require no confirmation per Pitfall #12 "live session never dies mid-set" composer-trust philosophy. |

**Voice/tone conventions (locked):**
- Lowercase first word of every advisory body (matches Flow's existing `[tuning] unmapped MIDI keys under …` precedent).
- Use the em-dash `—` to separate recovery action from main message (visually distinct from hyphens in identifiers).
- Avoid second-person commands ("You should…") — Flow advisories are observations, not instructions. Recovery sentences use imperative-without-subject ("restart `flow watch` to apply") or descriptive ("keeping previous version").
- Reserved bracket prefixes: `[live]`, `[osc]`, `[audio-in]`, `[watch]`, `[error]`, `[help]`. Researcher may NOT introduce new prefixes in Phase 38 without updating this table.
