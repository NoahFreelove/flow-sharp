loadFlowRuntime(): Promise<Runtime>   // throws Error('Flow runtime boot failed: ...') on boot fail
Runtime.run(source: string): Promise<RunResult>   // SYNCHRONOUS inside WASM; blocks event loop

RunResult: { wav?:Float32Array(null in v1), midi?:Uint8Array, stdout:string, stderr:string,
             errors:RunError[], durationMs:number }
RunError: { kind:"parse"|"eval"|"runtime"|"cancel"|"platform-not-supported", message:string,
            line?:number, column?:number, sourceSnippet?:string }
Default starter snippet: `use "@audio"\n(play (createSineTone 440Hz 1.0 0.5))` → audible 440 Hz on Run.

Gesture chain (HANDOFF §5, MANDATORY):
  runButton.onclick = async () => { await runtime.resumeAudio(); const r = await runtime.run(src); ... }
  NEVER call resumeAudio() on page load — silent no-op, no sound.

MIDI download (HANDOFF §9): if (r.midi) Blob([r.midi],{type:'audio/midi'}) → anchor.click().

Monaco (RESEARCH Pattern 3, Pitfall 1): SSR-incompatible. Import ONLY in onMount. `?worker` suffix for
  editor.worker; self.MonacoEnvironment.getWorker returns it. Single custom language → only the base
  editor.worker needed (no TS/JSON workers). Self-host Monaco (no CDN — RESEARCH Open Q1, keeps _headers tight).

Flow highlighting in Monaco (RESEARCH Open Q3 / A2): hand-written MONARCH tokenizer for v1 (NOT
  TextMate-in-Monaco — avoids the onigasm WASM payload). Derive keyword/type/note-literal/operator
  scopes from vscode-extension/syntaxes/flow.tmLanguage.json. Static doc/Home blocks already use shiki
  with the real grammar (Plan 49-04); the Monarch tokenizer is the editor-only derived view.

Console rendering (UI-SPEC §Playground, D-48-15): stdout = ink; stderr advisories = ink-muted labeled
  sub-region. errors[] → Rust-style boxes on .surface-paper with --color-danger left rail, ESCAPED TEXT

  raised in-browser — handle gracefully, don't surface a confusing "cancelled".

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `#code=` URL fragment → editor/runtime | Attacker-controllable Flow source enters Monaco + the WASM runtime |
| WASM runtime → browser audio | Flow executes in the Mono-WASM sandbox; runtime is the sandbox |
| RunResult → console DOM | stdout/stderr/errors strings rendered into the page |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-49-05-XSS | Tampering | console render of stdout/stderr/errors | mitigate | Render all RunResult strings as ESCAPED TEXT (`textContent`/Svelte `{...}` not `{@html}`); shared source loads into Monaco as text, never innerHTML (UI-SPEC V5 rule) |
| T-49-05-DoS | Denial of Service | runaway Flow script | accept | HANDOFF §4 — 30s cap is best-effort/non-preemptive in single-threaded WASM; a runaway script hangs only its own tab; document, optionally warn. No cross-user impact |
| T-49-05-BOOT | Information Disclosure | boot/run error text | mitigate | HANDOFF: RunError.message is sanitized server-side (T-48-15, no .NET stack traces leak); boot errors surface the friendly UI-SPEC copy, not raw internals |
| T-49-05-FRAG | Tampering | `#code=` decode | transfer | Defensive decode + size cap is implemented in Plan 49-06 (encode.ts); this plan loads the fragment guardedly and tolerates 49-06's absence |
</threat_model>
