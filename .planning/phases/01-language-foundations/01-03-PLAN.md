<objective>
Add ASCII piano-roll sequence visualization to the Flow language via a `visualize(Sequence)` built-in function.

Purpose: Users need quick visual feedback on their musical sequences without needing to render audio. A piano-roll ASCII grid shows pitch vs. time, making it easy to spot note patterns, timing issues, and rest placement. Per D-08/D-09/D-10, the output is a grid with pitch on Y axis, time on X axis, bar lines as `|`, and notes as horizontal bars.

Output: New VisualizationFunctions.cs with the visualize built-in, registration in BuiltInFunctions.cs, and test script.
</objective>

Create a static class `VisualizationFunctions` with a `public static Value Visualize(IReadOnlyList<Value> args)` method and a `public static void Register(InternalFunctionRegistry registry)` method.

`Register()`:

```csharp
public static void Register(InternalFunctionRegistry registry)
{
    var sig = new FunctionSignature("visualize", [SequenceType.Instance]);
    registry.Register("visualize", sig, Visualize);
}
```

`Visualize()` implementation (per D-08, D-09, D-10):

Step 1: Extract sequence data
- Get `SequenceData` from `args[0]` (use `args[0].Data as SequenceData` or however the Value unwrapping works -- read Value.cs to determine the pattern)
- Call `sequence.ToTimeline()` to get `List<(BarData bar, double offsetBeats)>`

Step 2: Collect all notes with position info
- Iterate through timeline bars
- For each bar, iterate through its `MusicalNotes` (or similar property -- READ SequenceType.cs carefully)
- For each note that is NOT a rest: record (midiPitch, startBeat, durationBeats)
- Use the existing `ToMidi()` approach for pitch conversion. If `TransformFunctions.ToMidi()` is private, replicate the MIDI conversion locally: `midiNumber = (octave + 1) * 12 + noteOffset` where noteOffset is C=0, C#=1, D=2, etc.
- For note duration, use `MusicalNoteData.GetBeats(timeSigDenominator)` -- read the BarData to find the time signature denominator
- Track cumulative beat position within each bar

Step 3: Determine grid dimensions
- Y axis: find min and max MIDI pitch across all notes. Add 1 row padding on each side if desired.
- X axis: total beats across all bars. Use a subdivision (e.g., 2 columns per beat for eighth-note resolution, or 1 column per beat for quarter-note resolution)
- Grid width = total beats * columns_per_beat
- Grid height = max_pitch - min_pitch + 1

Step 4: Build the grid (2D char array)
- Initialize all cells to space ' '
- For each note: fill cells from startColumn to startColumn + durationColumns with a block character. Use '#' or Unicode block character. '#' is safest for all terminals.
- For bar lines (per D-10): at each bar boundary beat position, set the column to '|' for ALL rows. Bar boundaries come from the timeline offsets.

Step 5: Render to string
- For each row (top = highest pitch, bottom = lowest pitch):
  - Print note name label (e.g., "C4", "D#5") left-padded to 4 chars
  - Print " |" separator
  - Print the row characters
- After all rows, print a beat number axis at the bottom
- Example output format:
```
  E4 |####    |        |
  D4 |    ####|        |
  C4 |        |########|
     +--------+--------+
      1   2    3   4
```

Step 6: Print to stdout via `Console.WriteLine()` and return `Value.Void()`

IMPORTANT: Read SequenceType.cs, NoteType.cs, and BarData carefully to understand the exact property names and data structures. The research mentions `SequenceData.ToTimeline()`, `BarData.MusicalNotes`, and `MusicalNoteData.GetBeats(timeSigDenominator)` but the exact API may differ. Also check if there is a `BarData.TimeSignature` property.
