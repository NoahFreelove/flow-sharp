<objective>
Add string interpolation with `$"...{expr}..."` syntax to the Flow language.

Purpose: Users currently must use verbose `(concat "text" (str expr) "text")` patterns for formatted output. String interpolation enables `$"tempo is {bpm}"` for dramatically simpler debugging and logging. Per D-05, the `$` prefix avoids conflicts with existing `{ }` used in musical context blocks, proc bodies, and sections.

Output: New InterpolatedStringExpression AST node, lexer interpolation scanning, parser assembly, evaluator concatenation, and test file.
</objective>

**Approach:** Use a multi-token sequence approach (per D-06, D-07). The lexer scans `$"..."` and produces a sequence of tokens: `InterpolatedStringStart`, then alternating `StringLiteral` (for text parts) and expression tokens (for `{expr}` parts), then `InterpolatedStringEnd`. The parser assembles these into an `InterpolatedStringExpression` with a `Parts` list of alternating `LiteralExpression` (strings) and arbitrary expressions.

**1. TokenType.cs** -- Add three new token types in the Literals section:
```csharp
InterpolatedStringStart,   // $"
InterpolatedStringEnd,     // " (closing an interpolated string)
InterpolatedStringText,    // Text segments between { } in interpolated strings
```

**2. InterpolatedStringExpression.cs** -- New file in `flow-lang/Ast/Expressions/`, namespace `FlowLang.Ast.Expressions`, using `FlowLang.Core`:
```csharp
/// <summary>
/// Represents a string interpolation expression: $"text {expr} text"
/// Parts is a list of expressions -- LiteralExpression for text segments,
/// arbitrary expressions for {expr} segments.
/// </summary>
public record InterpolatedStringExpression(
    SourceLocation Location,
    IReadOnlyList<Expression> Parts
) : Expression(Location);
```

**3. SimpleLexer.cs** -- Add detection of `$"` in the `NextToken()` method. Look for where character dispatch happens (likely a large `if/else` or `switch` on the current character). When `c == '$'` and the next character is `"`, call a new `ScanInterpolatedString()` method.

`ScanInterpolatedString()` implementation:
- Consume `$"` (advance past both characters)
- Emit `InterpolatedStringStart` token
- Return a list of tokens (or use a token buffer/queue pattern -- check how the lexer currently works; if it returns one token at a time from `NextToken()`, use a `Queue<Token> _pendingTokens` field)
- Scan characters:
  - Regular text characters: accumulate into a string builder
  - `{`: flush accumulated text as `InterpolatedStringText` token, then switch to normal lexing mode until matching `}` is found (per D-07, no nested braces -- just scan until first `}`). Lex the expression between `{` and `}` by collecting tokens until `}`.
  - `}`: end of expression segment, resume string scanning
  - `"`: end of interpolated string, flush any remaining text, emit `InterpolatedStringEnd`
  - `\\{`, `\\}`: escaped braces, treat as literal characters
- Handle escape sequences inside text segments same as regular strings (`\\n`, `\\t`, `\\"`, `\\\\`)

IMPORTANT: The lexer's `NextToken()` likely returns a single token. For multi-token output, use a `Queue<Token>` field. At the start of `NextToken()`, if the queue is not empty, dequeue and return. When `ScanInterpolatedString()` is called, it enqueues all the tokens for the entire interpolated string and returns the first one.

Alternative simpler approach: If the lexer structure makes a queue awkward, have `ScanInterpolatedString()` produce a single token of type `InterpolatedStringStart` whose `Value` property is a `List<object>` containing alternating strings and sub-token-lists. Then the parser handles the unpacking. Choose whichever approach fits better after reading the lexer code.

**4. Parser.cs** -- Add parsing for interpolated strings. In the expression parsing code (likely in `ParsePrimary()` or wherever `StringLiteral` is handled):

If using the multi-token approach:
```csharp
if (Match(TokenType.InterpolatedStringStart))
    return ParseInterpolatedString();
```

`ParseInterpolatedString()`:
- Collect parts: alternate between `InterpolatedStringText` tokens (wrap as `LiteralExpression` with string value) and expressions (parse normally until `}` token or `InterpolatedStringEnd`)
- Expect `InterpolatedStringEnd` at the end
- Return `new InterpolatedStringExpression(location, parts)`

**5. ExpressionEvaluator.cs** -- Add case in the `Evaluate()` switch expression:
```csharp
InterpolatedStringExpression interp => EvaluateInterpolatedString(interp),
```

Add `EvaluateInterpolatedString()`:
```csharp
private Value EvaluateInterpolatedString(InterpolatedStringExpression expr)
{
    var sb = new System.Text.StringBuilder();
    foreach (var part in expr.Parts)
    {
        var val = Evaluate(part);
        // Convert to string representation
        if (val.Data is string s)
            sb.Append(s);
        else
            sb.Append(val.Data?.ToString() ?? "");
    }
    return Value.String(sb.ToString());
}
```

Note: For non-string values, the interpolation should produce the same output as the `str` built-in function. Check how `str` converts different types in `stdlib.cs` and match that behavior. If `str` uses custom formatting (e.g., for floats), replicate it here or call the str function through the interpreter.
