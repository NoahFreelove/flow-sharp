    **1. Create `DSP/SidechainCompressor.cs`** (per D-09, D-10, D-11, D-16):

    Namespace: `FlowLang.StandardLibrary.Audio.DSP`

    Create `public static class SidechainCompressor` with:
    ```csharp
    public static AudioBuffer Apply(AudioBuffer source, AudioBuffer trigger,
        float thresholdDb, float ratio, float attackMs = 10f, float releaseMs = 100f)
    ```

    Implementation (reuses Compressor.cs envelope follower logic per D-10):
    - Guard: if source.Frames == 0, return empty buffer (follow existing DSP pattern)
    - Create `result = new AudioBuffer(source.Frames, source.Channels, source.SampleRate)`
    - Compute attack/release coefficients exactly as Compressor.cs does:
      `attackCoeff = attackMs > 0f ? (float)Math.Exp(-1.0 / (attackMs * 0.001 * source.SampleRate)) : 0f`
      `releaseCoeff = releaseMs > 0f ? (float)Math.Exp(-1.0 / (releaseMs * 0.001 * source.SampleRate)) : 0f`
    - Initialize `envelopeDb = -96f`
    - Loop over ALL source frames (per Pitfall 3 — iterate full source length, not min of trigger/source):
      - Peak detection on TRIGGER buffer (not source): if frame < trigger.Frames, find max abs across trigger channels; else use 0.0f (trigger naturally decays via release)
      - Convert peak to dB: `inputDb = trigPeak > 1e-10f ? 20f * MathF.Log10(trigPeak) : -96f`
      - Compute gain reduction: if inputDb > thresholdDb, `gainReductionDb = (inputDb - thresholdDb) * (1f - 1f / ratio)`
      - Smooth envelope with attack/release (same logic as Compressor.cs lines 56-83)
      - Convert to linear gain: `gainLinear = MathF.Pow(10f, envelopeDb / 20f)`
      - Apply gain to ALL source channels: `result.SetSample(frame, ch, source.GetSample(frame, ch) * gainLinear)`
    - Return result (new buffer, never mutates input per D-16)

    **2. Register in `EffectsFunctions.cs`**:
    Add a `RegisterSidechain(InternalFunctionRegistry registry)` private method. Call it from `Register()`.

    Register two overloads per D-11:
    - Simple (4 args): `sidechain(Buffer trigger, Buffer source, Double threshold, Double ratio)`
      ```csharp

          [BufferType.Instance, BufferType.Instance, DoubleType.Instance, DoubleType.Instance]);
      ```
    - Full (6 args): adds attackMs, releaseMs as Double
      ```csharp
      var sidechainFullSig = new FunctionSignature("sidechain",
          [BufferType.Instance, BufferType.Instance, DoubleType.Instance, DoubleType.Instance,
           DoubleType.Instance, DoubleType.Instance]);
      ```

    Lambda extracts args, casts to float, calls `SidechainCompressor.Apply(source, trigger, ...)`.
    NOTE: The Flow API is `sidechain(trigger, source, ...)` per D-09, so arg order is: args[0]=trigger, args[1]=source.

    The function is composable via `->` per D-17: `bass -> sidechain(kick, -12.0, 4.0)` — because `->` prepends to args, `bass` becomes the FIRST arg. But D-09 says signature is `sidechain(Buffer trigger, Buffer source, ...)`. This means when piped, `bass -> sidechain(kick, -12.0, 4.0)` becomes `sidechain(bass, kick, -12.0, 4.0)` — bass is trigger, kick is source. That seems backwards. Check D-09 carefully: "sidechain(Buffer trigger, Buffer source, Float threshold, Float ratio) -> Buffer". The idiomatic usage would be `bass -> sidechain(kick, -12.0, 4.0)` where bass=source and kick=trigger. So register as `sidechain(source, trigger, threshold, ratio)` to make the pipe work naturally: source is first (piped), trigger is second. The static method can take (source, trigger, ...) to match.
