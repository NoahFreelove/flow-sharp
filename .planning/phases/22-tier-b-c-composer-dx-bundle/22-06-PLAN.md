<objective>
DX-14: ship `legato(Sequence, Double)` and `portamento(Sequence, Millisecond)` articulation transforms.

`legato` extends each note's rendered duration by `(1 + overlap)`. Per CONTEXT D-01..D-03: notes are allowed to overlap into the next-note onset (true polyphonic legato, not gap-filling); MIDI export emits genuinely overlapping NoteOn/NoteOff events; the audio renderer's existing additive polyphonic mix handles overlap automatically.

`portamento` is a MIDI-only articulation in v1.3 (audio renderer ignores). MIDI export emits `CC65=127` (portamento on) + `CC5=mappedValue` (portamento time) at note start and `CC65=0` (portamento off) at note end. Mapping curve per Claude's Discretion in CONTEXT: linear `ms × 127 / 200` clamped to [0,127] (so 100ms → CC5=64, 200ms → CC5=127, anything beyond → 127 clamp).

Per Pitfall 3 (CRITICAL): legato MUST extend duration without moving onsets. Mechanism is a defaulted-parameter `DurationOverlap` field on `MusicalNoteData` read by `BarRenderer` post-`ToTimeline` and by `MidiExport` post-onset-tick — same pattern as existing `IsTied` at BarRenderer.cs:67-72.

This plan depends on 22-05 because both touch `MusicalNoteData` ctor (DX-13 added `OnsetOffset`; this plan appends `DurationOverlap` + `PortamentoMs`). Sequencing avoids a double-migration of the same constructor.

Output: 2 new defaulted fields on MusicalNoteData; BarRenderer + MidiExport extensions; transform registrations; smoke + Facts including DryWetMidi read-back.
