## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Composer flow script → loadSfz builtin | Symbol or string argument crosses here — already type-checked by the type system |
| FlowConfig.Active.SfzRoot → File.ReadAllText | Composer-controlled config string; same posture as Phase 32 loadScala which accepts arbitrary paths |
| External .sfz file → SfzParser | Untrusted file content (length, regions, opcodes) crosses here — Plan 33-04 handles parser-side mitigations |

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-33-PATH-01 | InfoDisclosure | absolute sample paths inside symbol-resolved .sfz files | accept | For Plan 33-05 v1: the absolute-path String overload is the documented bypass-the-dict contract. Symbol-resolved loads use Path.Combine(sfz_root, relative) which already canonicalizes via .NET — defense-in-depth path-containment is deferred to a v1.5 follow-up |
| T-33-IO-01 | InfoDisclosure | reading an arbitrary file via FlowConfig.SfzRoot path | accept | Phase 32 loadScala precedent — composer-controlled config; same posture as writeWav("/etc/foo") |
| T-33-PITFALL-2 | Tampering (test-side) | FlowConfig.Active singleton mutation between loadSfz calls | mitigate | Cache resolved sfz_root in ExecutionContext.ResolvedSfzRoot on first call (Pitfall 2) — prevents singleton-pollution test flakes and prevents script-time config edits from affecting an in-flight render |
