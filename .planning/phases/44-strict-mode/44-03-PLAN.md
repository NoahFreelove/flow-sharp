<objective>
Disable OverloadResolver's "+100 convertible" tier when `ctx.StrictMode==true`. Two implicit-conversion clauses in `FunctionSignature.Matches` are dropped under strict per RESEARCH Pitfall 1: (a) `argTypes[i].CanConvertTo(InputTypes[i])` covering numeric widening (Int → Long → Float → Double), and (b) `InputTypes[i].IsCompatibleWith(argTypes[i])` covering inverse-direction music-type widening (`Decibel.IsCompatibleWith(Double)=true` makes `(gain buf -12.0)` accept the raw Double under non-strict). The strict path requires `argTypes[i].Equals(InputTypes[i])` (exact) OR `argTypes[i].IsCompatibleWith(InputTypes[i])` (compatible) only — the two acceptance clauses scoring +1000 / +500 in the existing specificity table.

Purpose: Axis A is THE strict-mode definition of "no type coercion". Pitfall 1 is the most dangerous landmine of the phase — a naive read of "+100 tier" only catches the numeric-widening clause and leaves music-type widening intact, silently passing strict tests for `(gain buf -12.0)` that should fail. Plan 44-03 owns the predicate filter + the verbatim two-clause test cases.

Output: One bool parameter through Matches + Resolve + ResolveFunction (Pitfall 4 explicit-parameter route), one read of ctx.StrictMode at ExecutionContext.ResolveFunction, one Phase44 test file pinning both clauses.
</objective>
