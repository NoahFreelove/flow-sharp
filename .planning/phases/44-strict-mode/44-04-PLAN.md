<objective>
Ship the 6 forward + 4 reverse explicit-conversion builtins per D-08/D-09/D-10. All 6 forward (`db`/`hz`/`ms`/`sec`/`cents`/`semitones`) are available in BOTH modes so composers can incrementally refactor toward strict one call at a time. The 4 reverse extractors (`double`/`float`/`int`/`long`) gain overloads accepting all 6 tagged music types (Decibel/Hertz/Cent/Millisecond/Second/Semitone). This plan runs in parallel to Plan 44-03 — both depend only on Plan 44-01's pragma foundation.

Purpose: explicit conversions are the SAFETY NET for Axis A. Without `(db x)` etc., a composer hitting Axis A errors has no path forward except `(double (db -12.0))` workarounds. The forward builtins make strict-mode refactoring practical; the reverse extractors close the round-trip.

Output: One new file `ConversionFunctions.cs` registering 25 forward + 1 semitones + 24 reverse = 50 builtin registrations, one wire-up edit in `BuiltInFunctions.cs`, two Phase44 test files covering the full matrix.
</objective>
