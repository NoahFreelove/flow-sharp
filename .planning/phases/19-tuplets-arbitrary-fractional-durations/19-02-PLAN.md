Per RESEARCH §Pattern 3 + §Pitfall Phase-19-specific lexer-vs-parser disambiguation: this work is **parser-only** — the lexer already emits `Slash` (TokenType.Slash), `IntLiteral`, `Colon`, and `Identifier(q/h/...)` as separate tokens. Per SPEC TUP-04 D-USER-H lock: `C4/1` is valid (= whole note); `C4/0` is a parse error. Per SPEC TUP-08 acceptance: `C4/0:2` raises `"Tuplet ratio numerator X must be ≥ 1; got 0"`.

C4:50 E4:50)` random-choice weights and `D4/3:2` per-note tuplet ratios coexist without parser ambiguity. The disambiguation is structural — random choice is gated by `(?` outer paren; per-note `/X:Y` happens AFTER a `Slash` token. AST shapes don't overlap.

The encoding choice for TUP-04 (`C4/N`) follows RESEARCH §Code Examples Example 2 sketch: encode as `TupletRatio = (N, 1)` so the compiler can branch `if (Y == 1) /* TUP-04 path: 1/N whole = 4/N quarter */ else /* TUP-08 path */`. The `(N, 1)` shape collides with no real tuplet ratio (`X:1` is musically meaningless — you cannot play N notes in the time of 1 normal note unless N=1, which is a no-op). This sentinel is internal-only and never user-visible.

User-facing `C4/3:1` would be rejected by the same compile-time check if anyone wrote it; the parser does not specifically reject it because the SPEC does not call for it (Y=1 user-typed is unspecified behavior per SPEC TUP-08; sentinel-overlap is acceptable since `C4/3` and `C4/3:1` are mathematically equivalent).
