<objective>
Ship SPEC-2: three context-aware completion filters applied to the existing 5-source merge in `CompletionHandler.BuildItems` (CompletionHandler.cs:121-125).

1. **FilterByImports** — drops stdlib procs whose `StdProc.Module` does not appear in the file's set of imported modules. Special case: `use "@std"` transitively imports every stdlib module (use `StdlibSymbolIndex.ModuleNames` to expand).
2. **FilterByPragmas** — drops note-stream-only completions that require a pragma not in `ast.Pragmas`. Concrete: `H4`/`H5` (and other H-notes) are removed unless `enable hAsB;` is declared.
3. **BoostByMusicalContext** — inside a `key { ... }` block, raises the priority of roman-numeral completions (`I`, `ii`, `IV`, `V7`, `vi`) and chord builtins so they appear at the top of the list. Outside key context, leaves the ranking alone.

Each filter is a `public static` helper following the Phase 17 idiom (CompletionHandler.cs:65-191 already exposes SnippetTemplates, IsInsideUseStringLiteral, RomanNumeralItems as static helpers — match that shape). Pure transforms — input `IEnumerable<CompletionItem>`, output `IEnumerable<CompletionItem>`. Unit-testable without OmniSharp transport.

Purpose: Composer's completion list reflects what's actually reachable in the current file — no more "why is `arpeggio` suggested when I haven't imported it?" friction.

Output: 1 modified handler + 1 new test fact class.
</objective>
