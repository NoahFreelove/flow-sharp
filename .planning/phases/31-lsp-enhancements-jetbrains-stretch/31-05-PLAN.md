<objective>
Ship SPEC-3: variadic function shapes render as `name: Type…` (D-02) using Unicode horizontal ellipsis `…` (U+2026, D-01) in:
1. Hover panel — `HoverHandler.BuildHover` for any builtin whose FunctionSignature.IsVarArgs is true.
2. Signature help — `SignatureHelpHandler.Handle` SignatureInformation.Label.
3. Completion tooltips — through the same FormatSignature path (CompletionHandler builds tooltips from the same Signatures array).

Per CONTEXT D-01: Unicode `…` (U+2026), NOT ASCII three dots. Re-confirmed in plan-phase D-12 (the orchestrator's planning_context note proposed ASCII but the CONTEXT.md decision is authoritative).

flow-lang stays untouched per Phase 24 D-04 "zero flow-lang touch for LSP-only work" — `FunctionSignature.ToString()` continues to emit "..." for runtime use; the LSP-side `LspMappings.FormatSignature` is the new layer that renders the Unicode ellipsis.

Pitfall 3 mitigation: populate `SignatureInformation.Parameters` with explicit `ParameterInformation` ranges via `LspMappings.BuildParameters(FunctionSignature)` so active-parameter highlighting works correctly regardless of UTF-8 byte width of the U+2026 character.

Output: 1 modified utility (LspMappings) + 2 modified handlers (Hover, SignatureHelp) + 1 new test fact class.
</objective>
