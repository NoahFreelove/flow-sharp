### Integration Gap

**`section { gain N { | notes | } }` produces 0 frames.**
`Interpreter.ExecuteSectionDeclaration` (`flow-lang/Interpreter/Interpreter.cs:347-406`) captures `_lastExpressionValue` only from top-level `ExpressionStatement`s inside `section.Body`. When a bare note-stream lives inside a nested `MusicalContextStatement` (gain/tempo/timesig/key), it is never seen. Same breakage for any context keyword nested inside a section. This is the intersection of **FIX-02** (Phase 6) and **AUDIO-06** (Phase 8). The limitation predates phase 8, but phase 8's `gain` keyword made it user-visible through natural composition.

**Suggested fix:** recursively walk `MusicalContextStatement.Body` during bare-expression capture, or capture inside `ExecuteMusicalContext` when the enclosing frame is a section.

## FIX-04 Reclassification

The 06-01 SUMMARY marks FIX-04 as N/A and cites "file does not exist." That rationale is wrong — `flow-interpreter/LiveReloadManager.cs` does exist (390 lines, created in phase 5). The conclusion is nevertheless correct: the bug premise does not hold in the current architecture.

Evidence:
- `flow-lang/StandardLibrary/Audio/PlaybackFunctions.cs:20` captures the `AudioPlaybackManager` via per-registration closure. No static `_manager` field, no `GetManager()`/`SetManager()` methods exist.
- Each `FlowEngine` owns its own `AudioPlaybackManager` (`Program.cs:71,99`).
- `LiveReloadManager.cs:344` creates a fresh `FlowEngine` per re-render and maintains a separate `_streamingManager` (`:39`) for live playback.

No static state is shared across engines, so clobbering is structurally impossible. Reclassify FIX-04 as `invalid — premise does not hold` and update the SUMMARY rationale.
