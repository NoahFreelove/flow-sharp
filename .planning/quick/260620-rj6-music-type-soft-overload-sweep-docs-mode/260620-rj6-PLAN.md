<objective>
Add a fixed, audit-derived set of music-type soft-overloads so typed music literals
(`+50c`, `-12dB`, `1.0s`, `440Hz`, `+2st`, `0.5b`) resolve at the exact +1000 tier of
the OverloadResolver for builtins whose params today only accept raw numerics — then
modernize all docs/examples to the typed forms. The mechanic: every music type wraps
double (Semitone wraps int) and `IsCompatibleWith(Double/Float)` is true, so each typed
literal already binds at +500; registering the SAME implementation lambda under a
music-typed `FunctionSignature` promotes it to an exact +1000 match (zero coercion —
the CLR backing IS double/int, read via `args[i].As<double>()`/`As<int>()`). The model
is `createSineTone` (BuiltInFunctions.cs:831-854).

Purpose: route literals to the correct slot in multi-param functions, fix two
CORRECTNESS gaps (Cent on trill/repeat currently throws; only the full dB compress/
sidechain forms are dB-typed), and document intent at the type-system level.
Output: new overload registrations + .flow proc overloads + modernized wiki/docs/examples.
