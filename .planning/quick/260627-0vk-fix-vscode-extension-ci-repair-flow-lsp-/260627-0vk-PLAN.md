# Quick Task 260627-0vk — Fix the VSCode extension CI

## Root cause (diagnosed, reproduced locally)

The `publish-extension.yml` `build-server` job fails at the **"Smoke-test the LSP
binary"** step on osx-arm64 — `fail-fast: true` then cancels the other 3 legs and
`publish` is skipped. (Earlier assumption "missing marketplace secrets" was WRONG
— publish never even runs.)

Reproduced on **linux-x64** locally: `scripts/lsp-smoke.sh` exits 3 ("did not exit
within timeout"). The flow-lsp binary is fine — it boots, replies to `initialize`,
and exits cleanly (code 0) when driven correctly. The harness is the bug: it writes
all four messages (`initialize`/`initialized`/`shutdown`/`exit`) in one
`communicate()` burst and only reads stdout *after* writing, so the server never
completes the `initialize` handshake before `exit` and hangs. A real LSP client
drains stdout continuously.

Verified locally that the FULL build-server pipeline is otherwise green: publish
flow-lsp → copy 15 stdlib .flow → smoke (with fix) → `npm ci` → `tsc` → grammar
snapshots 6/6 → `vsce package` → 34 MB VSIX.

## Tasks

### Task 1 — Repair `scripts/lsp-smoke.sh`
- **files:** `scripts/lsp-smoke.sh`
- **action:** Replace the Python driver with one that (a) drains stdout AND stderr
  concurrently in background threads, (b) sends `initialize`+`initialized` and waits
  for the framed `initialize` response BEFORE sending `shutdown`+`exit`, (c) asserts
  boot+framed-response as the load-bearing check, and (d) attempts graceful exit but
  force-kills + still PASSES if the server lingers (editor force-kills too; exit
  timing must never red the build). Keep the bash wrapper (arg parse, existence
  check, chmod) unchanged.
- **verify:** `bash scripts/lsp-smoke.sh <freshly-published flow-lsp>` exits 0,
  twice (determinism), in ~1s.
- **done:** smoke passes locally against the published linux-x64 binary.

### Task 2 — Harden `publish-extension.yml`
- **files:** `.github/workflows/publish-extension.yml`
- **action:** (a) build-server `fail-fast: true` → `false` so one platform's failure
  doesn't cancel the others. (b) Secret-guard the publish job: map `VSCE_PAT`/
  `OVSX_PAT` to job `env`, gate each marketplace step on `env.X != ''`, and add a
  `::notice::` skip step per registry when unset — so a `v*` tag push is GREEN
  whether or not marketplace secrets are configured, and publishing auto-activates
  once they're added.
- **verify:** `python3 yaml.safe_load(...)` parses; `fail-fast: false` present; the
  4 guarded steps reference `env.VSCE_PAT`/`env.OVSX_PAT`.
- **done:** workflow parses; no false-fail path remains for an unconfigured repo.
