# Quick Task 260524-n96: Resolve Fixtures/fixtures directory case-collision

## Outcome

Pre-existing cross-platform latent bug closed. Both `flow-lang.Tests/Fixtures/` and `flow-lang.Tests/fixtures/` existed as distinct directories on Linux (case-sensitive ext4); on macOS APFS (default case-insensitive) and Windows NTFS they would silently merge with last-write-wins data loss for any composer cloning the repo on a non-Linux machine.

Resolved by collapsing both into a single canonical lowercase `fixtures/` directory.

## Canonical-casing decision

**Lowercase `fixtures/` (overrode my PascalCase recommendation).** Planner's reasoning:
- Reference-count: ~40 lowercase sites across Phase 32/33/37 vs ~10 PascalCase across Phase 29/30/37 — migrating to lowercase touches 4× fewer sites
- `examples/scala/intro.flow` already established lowercase precedent
- C# namespace `FlowLang.Tests.Fixtures` (PascalCase) stays unchanged — disk path is independent of the C# namespace declaration, so the 15 `using FlowLang.Tests.Fixtures;` consumer directives need no edits

## What changed

17 files in one atomic commit (`e0d7274`):
- 12 file renames `Fixtures/* → fixtures/*` (per-file `git mv`, history preserved via `git log --follow`)
- 5 reference modifications: `flow-lang.Tests/Tools/Phase29BaselineRecorder.cs`, `Integration/Phase29/HarmonicRichnessTests.cs`, `Integration/Phase30/Midi2FlowRoundTripTests.cs`, `Integration/Phase37/Phase37RmsRegression.cs`, `flow-lang.Tests.csproj`
- Of those, 3 are rename-with-modify (`writeMidi` path strings inside `drum_loop.flow`, `ragtime_q_ee.flow`, `two_voice_counterpoint.flow` at 85-86% similarity)

## Key planner catch

`flow-lang.Tests.csproj` had 3 `<None Update="Fixtures\midi\*.mid">` entries that would have silently broken Phase 30 Midi2Flow round-trip tests via `AppContext.BaseDirectory` copy-to-output. Easy to miss in a pure-rename pass.
