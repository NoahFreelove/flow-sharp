# Quick 260621-x21: Add Additive Symbol Overloads to renderSong Summary

Added two additive `renderSong` overloads so composers can pass a Symbol instrument name — `(renderSong song #piano)` and `(renderSong song #piano release=2.0s)` — alongside the existing String forms; both unwrap the symbol's interned name and delegate to the existing String render path, producing byte-identical output.

## What Was Built

**Task 1 — C# overloads (`flow-lang/StandardLibrary/Audio/SongRenderer.cs`):**
- Two new `FunctionSignature` registrations in `SongRenderer.Register`, added AFTER the existing `releaseSig` registration (existing String registrations untouched):
  - `renderSong(Song, Symbol)` → `RenderSongFromSymbol`
  - `renderSong(Song, Symbol, Second)` → `RenderSongFromSymbolWithRelease` (ParameterNames `song`/`instrument`/`release` mirror `releaseSig` so `release=` named-arg resolution works).
- Two new thin private handlers placed next to `RenderSongWithRelease`. Each reads the symbol name via the established accessor `args[1].As<string>()` (mirrors `SfzBuiltins.LoadSfzSymbol` — a Symbol Value's `.Data` IS the interned name string), rebuilds the args list with a `Value.String(synthType)` in slot 1, and delegates — `RenderSongFromSymbol` → `RenderSong`, `RenderSongFromSymbolWithRelease` → `RenderSongWithRelease` (carrying the Second `release` arg through unchanged in slot 2). No rendering logic duplicated.
- `SymbolType` was already in scope via the existing `using FlowLang.TypeSystem.PrimitiveTypes;` (line 13) — no new using added.

**Task 2 — .flow reachability surface (`flow-lang/audio.flow`):**
- Added `internal proc renderSong(Song: song, Symbol: synthType)` right after the existing `String`/`Function` renderSong procs, and `internal proc renderSong(Song: song, Symbol: synthType, Second: release)` right after the existing `String+Second` proc. Without these, `(renderSong song #piano)` fails overload resolution even though the C# overload is registered (CLAUDE.md "Adding Built-ins" + external memory `project_adding_builtins_needs_flow_surface.md`).
- All four pre-existing renderSong procs (String, Function, String+Second) unchanged.

**Task 3 — verification (no code changes):** see below.
