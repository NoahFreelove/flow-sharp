## Decisions Made

- **Local `notBool` helper.** Grep against `StandardLibrary/BuiltInFunctions.cs` confirmed there is no `not` primitive; implementing `(if b false true)` as a one-line helper is cheaper than adding a built-in and keeps `test.flow` self-contained.
- **`(if cond passStr failStr)` instead of branching `print` calls.** Flow's eager `if` overload evaluates both branches as arguments before dispatch, so `(if passed (print A) (print B))` prints both lines. Selecting the prefix string inside `if` and calling `(print line)` once is the idiomatic fix (same pattern as `tests/test_custom_oscillator.flow`).
- **`reduce`-based tally in `summary`.** Keeps the library purely functional and sidesteps the lack of a mutable-counter idiom.

**1. [Rule 3 - Blocking] Added test.flow to flow-lang.csproj CopyToOutputDirectory list**

**2. [Rule 1 - Bug] Refactored printResult to print exactly once**
- **Found during:** Task 2 (running tests/test_test_library.flow to verify PASS/FAIL counts)
- **Issue:** The initial printResult used `(if passed (print passLine) (print failLine))`. Flow's eager `if (Bool, Void, Void)` overload evaluates both argument expressions before dispatch, so every assertion emitted both a PASS and a FAIL line, producing 19 PASS + 19 FAIL lines (38 total) instead of the intended 10 PASS + 9 FAIL. Final `summary` numbers were still correct because the return `Bool` was unaffected, but the PASS/FAIL trace was garbage.
- **Fix:** Restructured printResult to select the prefix string with `(if passed "PASS: " "FAIL: ")`, compose a single line via `concat`, and call `(print line)` once. This matches the `(print (if cond passStr failStr))` idiom already used in `tests/test_custom_oscillator.flow`.
- **Files modified:** `flow-lang/test.flow` (printResult body only)
- **Verification:** Re-running `tests/test_test_library.flow` now emits exactly 10 PASS lines and 9 FAIL lines; `grep -q "Passed: 10"`, `grep -q "Failed: 9"`, `grep -q "Total:  19"`, and the completion marker grep all pass; `grep -E "Error:|Unhandled exception" /tmp/flow-test-lib.out` is empty.
- **Committed in:** `c8731d2` (Task 2 commit)

## Follow-ups

- **Consider adding a built-in `not` primitive** so future pure-Flow code doesn't have to re-implement `notBool`. Low priority — the helper is trivial.
- **Consider promoting `@test` via `@std` aggregate import.** Currently `use "@std"` loads `@collections` and `@bars` but not `@test`. Keeping `@test` opt-in is probably correct (not every script wants assertion procs), but worth revisiting if a "testing mode" convention emerges.
- **Consider a strict `if` overload that short-circuits.** The current eager `if (Bool, Void, Void)` overload is what caused the Task 2 bug. A `(whenTrue cond lazyAction)` or lazy-only `if` convention would reduce footguns. Out of scope for this quick task.
- **Consider documentation / wiki update.** If the wiki has a "Testing Flow Scripts" page, `@test` should be linked there with a usage example.
