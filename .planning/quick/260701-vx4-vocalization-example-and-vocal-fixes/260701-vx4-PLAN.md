# Quick Task 260701-vx4: Vocalization example + charitable vocal-stdlib fixes

## Goal

Three deliverables:

1. **Playground example** — a musical ~12 s vocal piece (`flow-site/static/examples/vocal-choir.flow`)
   that shows off `sing` (pure formant synthesis, audible in the browser WASM playground): a vowel
   choir singing a chord progression (stacked `sing` buffers `mix`ed into chords), a CV-syllable
   melodic line (`appendBuffers` per syllable), gentle reverb, and a soft synthesized triangle pad.
   Robotic Kraftwerk-vocoder character is expected and part of the charm. One `manifest.json` entry.

2. **Charitable phoneme fallback** (`FormantData.GetFormants`) — an unknown phoneme currently THROWS
   `ArgumentException`, violating the house charitable-interpretation philosophy. Fall back to the
   `"ah"` vowel + a one-shot stderr advisory, preserving valid-phoneme behavior byte-identically.

3. **tts Web-target guard** (`TtsHook.RunTts`) — on the Web target `(tts "...")` hard-crashes with a
   raw `PlatformNotSupportedException` from `Process.Start`. Wrap the process path with `#if !FLOW_WEB`;
   on Web return a short silent buffer + one-shot advisory pointing composers at `sing`.

## Runtime-version constraint (CRITICAL)

The committed WASM bundle (`flow-site/static/wasm/`, synced 2026-06-26) PREDATES today's resolver fix
(commits 7962c61 / aa25f7a). The example must behave identically on old and new runtimes:

- RAW DOUBLE SECONDS durations everywhere: `(sing "ah" C4 0.5)` NOT `(sing "ah" C4 500ms)`.
- Tone generators via the Hz-first / Double-duration shape `(createTriangleTone 220Hz 8.0 0.15)`
  (proven by the committed `sine-440.flow`), NOT the new `(… 220Hz 8.0s …)` Second form.
- `createSilence` NOT the new `silence` alias.
- Do NOT bind `(applyEnvelope …)` results (returned Void on the old runtime).
- Effects (reverb / gain / mix / appendBuffers / pan / lowpass / volume / fadeIn) are fine.
- NO sampled instruments (piano/strings/etc.) — silent on web. Synthesis only. NEVER `tts` (crashes on web).

The flow-lang changes (fallback + tts guard) reach the LIVE playground only after a future
`bash flow-site/scripts/sync-runtime.sh` bundle regen. The example itself works on the CURRENT bundle
because it avoids new-runtime-only call shapes.
