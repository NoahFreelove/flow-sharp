# Quick Task 260627-09v — Tag-driven GitHub Actions release for the flow CLI

## Why

The repo already has `scripts/publish.sh` (Phase 41 BIN-01) that cross-compiles
the 5 self-contained single-file `flow` binaries (linux-x64/arm64, osx-x64/arm64,
win-x64), packages them as `flow-<rid>-v<VERSION>.{tar.gz,zip}` + `.sha256`, and
`scripts/install.sh` is a `curl`-able installer that pulls those exact assets off
a **GitHub Release**. But nothing runs `publish.sh` in CI and no v1.5.0 Release
exists — the only release asset anywhere is a stale hand-uploaded
`flow-linux-x64.tar.gz` on `v1.4.0`. So `install.sh` for v1.5.0 points at assets
that don't exist. "v1.5.0 GitHub Release cut" is also one of the 7 open Phase 41
HUMAN-UAT gates.

This wires the proven `publish.sh` into a tag-driven Actions workflow so a pushed
`v*` tag builds all 5 binaries + checksums and publishes them to a GitHub Release.

Build is confirmed green locally (linux-x64 publishes; `flow version` → 1.5.0).

## Constraints (owner-locked)

- Build ONLY on a pushed `v*` tag — no `workflow_dispatch`, no push/PR builds.
- Do NOT modify `publish-extension.yml` or `wiki-sync.yml`.
- Do NOT push any git tag and do NOT create a release in this task (CI-only landing).
- Tag-protection ruleset (only owner/admins create/modify tags) is handled
  separately as a `gh api` infra action — not a repo file edit, tracked in SUMMARY.

## Tasks

### Task 1 — Add `.github/workflows/release.yml`
- **files:** `.github/workflows/release.yml` (new)
- **action:** Tag-driven workflow: `on.push.tags: ['v*']` only; `permissions:
  contents: write`; single `ubuntu-latest` job: checkout → setup-dotnet 10.0.x →
  ensure `zip` → `bash scripts/publish.sh` with `VERSION=${{ github.ref_name }}` →
  `gh release create` attaching every `publish/flow-*-<tag>.{tar.gz,zip}` +
  `.sha256`. Hyphenated tag (e.g. `v1.5.0-rc1`) → `--prerelease`; clean tag → full
  release. `--generate-notes`.
- **verify:** `python3 -c "import yaml; yaml.safe_load(open('.github/workflows/release.yml'))"` parses.
- **done:** workflow file exists and parses as valid YAML.

### Task 2 — Generalize `scripts/publish.sh` version
- **files:** `scripts/publish.sh`
- **action:** Change `VERSION="v1.5.0"` → `VERSION="${VERSION:-v1.5.0}"` so the
  workflow overrides via the `VERSION` env var while local runs keep the default.
- **verify:** `bash -n scripts/publish.sh` parses clean; `VERSION=v9.9.9 bash -c
  'source <(grep VERSION= scripts/publish.sh | head -1); echo $VERSION'` → v9.9.9.
- **done:** override works, local default preserved.

## must_haves
- truths:
  - The release workflow triggers on `v*` tags and nothing else.
  - `publish.sh` honors a `VERSION` env override, defaulting to `v1.5.0`.
- artifacts:
  - `.github/workflows/release.yml`
  - `scripts/publish.sh` (one-line version change)
- key_links:
  - `scripts/publish.sh` (build/package/checksum logic reused verbatim)
  - `scripts/install.sh` (consumes the published `flow-<rid>-v<VERSION>.tar.gz` assets)
