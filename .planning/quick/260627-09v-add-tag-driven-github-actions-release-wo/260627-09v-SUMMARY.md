# Quick Task 260627-09v — SUMMARY

## What shipped

1. **`.github/workflows/release.yml`** (new) — tag-driven release CI.
   - Trigger: `on.push.tags: ['v*']` **only**. No `workflow_dispatch`, no
     push/PR builds (owner-locked: "only build on a tagged release").
   - One `ubuntu-latest` job: checkout → `setup-dotnet@v4` 10.0.x → ensure `zip`
     → `bash scripts/publish.sh` (VERSION = `github.ref_name`) → `gh release
     create` attaching every `publish/flow-*-<tag>.{tar.gz,zip}` + `.sha256`.
   - Hyphenated tag (e.g. `v1.5.0-rc1`) → `--prerelease` (safe dry-run path);
     clean tag (`v1.5.0`) → full release. `--generate-notes` on both.
   - Uses the preinstalled `gh` CLI + `GITHUB_TOKEN` (`permissions: contents:
     write`) — no third-party action, no marketplace secrets.

2. **`scripts/publish.sh`** — `VERSION="v1.5.0"` → `VERSION="${VERSION:-v1.5.0}"`.
   The workflow overrides it from the tag; local runs keep the v1.5.0 default.
   Asset naming (`flow-<rid>-v<VERSION>.tar.gz`) is exactly what `scripts/install.sh`
   fetches, so a pushed tag produces install-ready assets.

3. **GitHub tag-protection ruleset** (infra, not a repo file) — `gh api POST
   repos/NoahFreelove/flow-sharp/rulesets`, id **18198492**, enforcement active.
   - target=tag, conditions ref_name include=`~ALL` (all tags).
   - rules: `creation`, `update`, `deletion` restricted.
   - bypass: `RepositoryRole` actor_id 5 = **Repository admin**, mode `always`.
   - Net: only the owner/admins can create or modify any tag; write
     collaborators cannot. The release workflow is *triggered by* tags (never
     creates them), so protection does not block releases.
