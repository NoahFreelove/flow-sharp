<objective>
Change the note-stream bare (undurated) note default duration from the current auto-fit-by-count behavior to the **time-signature denominator's note value (the musical pulse)**, and change bar overflow from silent-spill / silent-truncate to **always-warn-but-still-play (spill, never drop)** across BOTH the bare/suffix path and the tuplet/fraction path.

Purpose: The current `CalculateAutoFitDuration` divides the bar evenly by the count of undurated elements and snaps to the nearest standard note value. This is LUMPY (5 bare notes render longer than 6 or 8) and it spills past the barline silently. The composer-locked target: a bare note's duration = the denominator's pulse (4/4 → quarter, 6/8 → eighth, 2/2 → half), independent of count, with a loud (but non-fatal) advisory whenever a bar's content overflows the meter — and all notes always play.

Output: A single-file core change in `NoteStreamCompiler.cs` plus tests (one `.flow` composer test via the `@test` `assertNotesMatch` surface, one precise xUnit test, and a rewrite of the two TUP-05 truncation tests to assert spill), plus regenerated RMS/WAV baselines for any scripts whose bare-note bars legitimately retime.

Charitable interpretation throughout (project memory): never throw; degenerate cases (non-power-of-2 denominator, empty bar, all-rests) fall back to quarter / no-advisory. The overflow advisory is informational (stderr), not an accumulated error — the ErrorReporter error path is untouched.
</objective>
