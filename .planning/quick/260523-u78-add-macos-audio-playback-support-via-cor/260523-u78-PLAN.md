<coreaudio_reference>
<!-- Critical AudioQueue API surface the executor needs. Apple AudioToolbox framework, public API. -->

DllImport path: `/System/Library/Frameworks/AudioToolbox.framework/AudioToolbox`

AudioStreamBasicDescription (struct):
```
[StructLayout(LayoutKind.Sequential)]
struct AudioStreamBasicDescription {
    public double mSampleRate;          // e.g. 44100.0
    public uint   mFormatID;            // 'lpcm' = 0x6C70636D (kAudioFormatLinearPCM)
    public uint   mFormatFlags;         // kAudioFormatFlagIsFloat (1) | kAudioFormatFlagIsPacked (8) = 9
    public uint   mBytesPerPacket;      // channels * 4 (sizeof float)
    public uint   mFramesPerPacket;     // 1 for PCM
    public uint   mBytesPerFrame;       // channels * 4
    public uint   mChannelsPerFrame;    // 1 or 2
    public uint   mBitsPerChannel;      // 32
    public uint   mReserved;            // 0
}
```

AudioQueueBuffer (struct — only first 3 fields needed):
```
[StructLayout(LayoutKind.Sequential)]
struct AudioQueueBuffer {
    public uint   mAudioDataBytesCapacity;
    public IntPtr mAudioData;
    public uint   mAudioDataByteSize;
    // ... more fields (mUserData, mPacketDescriptionCapacity, etc.) — not needed
}
```

Callback signature (managed → unmanaged via UnmanagedCallersOnly or GetFunctionPointerForDelegate):
```
delegate void AudioQueueOutputCallback(IntPtr userData, IntPtr aq, IntPtr buffer);
```

Core API calls:
- `OSStatus AudioQueueNewOutput(ref AudioStreamBasicDescription inFormat, IntPtr inCallbackProc, IntPtr inUserData, IntPtr inCallbackRunLoop, IntPtr inCallbackRunLoopMode, uint inFlags, out IntPtr outAQ)`
- `OSStatus AudioQueueAllocateBuffer(IntPtr inAQ, uint inBufferByteSize, out IntPtr outBuffer)`
- `OSStatus AudioQueueEnqueueBuffer(IntPtr inAQ, IntPtr inBuffer, uint inNumPacketDescs, IntPtr inPacketDescs)`
- `OSStatus AudioQueueStart(IntPtr inAQ, IntPtr inStartTime)` — pass IntPtr.Zero to start immediately
- `OSStatus AudioQueueStop(IntPtr inAQ, bool inImmediate)`
- `OSStatus AudioQueueDispose(IntPtr inAQ, bool inImmediate)`

OSStatus 0 = noErr (success). Non-zero = error code.

Format flag constants:
- `kAudioFormatLinearPCM = 0x6C70636D` ('lpcm' big-endian fourcc)
- `kAudioFormatFlagIsFloat = 1`
- `kAudioFormatFlagIsPacked = 8`
- Combined: `0x09`

<implementation_strategy>
<!-- Simplest working AudioQueue blocking-play loop. Composer trust, not maximum efficiency. -->

For `Play(float[] samples, ...)`:
1. Initialize the queue if not already (or if format changed) — populate `AudioStreamBasicDescription`, call `AudioQueueNewOutput`.
2. Use a SIMPLE push-mode strategy (no callback-driven refill needed for blocking play):
   - Allocate 3 buffers via `AudioQueueAllocateBuffer`, each sized to ~4096 samples × bytesPerFrame.
   - In a loop: copy the next chunk of source samples into a buffer's `mAudioData` (via `Marshal.Copy`), set `mAudioDataByteSize`, call `AudioQueueEnqueueBuffer`.
   - When all 3 buffers are queued, call `AudioQueueStart`.
   - For subsequent chunks, use a callback that signals a `ManualResetEventSlim` when a buffer is consumed — wait on it, then refill+enqueue.
   - Honor `CancellationToken`: if cancelled mid-stream, call `AudioQueueStop(immediate: true)` and return.
3. After the last chunk is enqueued, call `AudioQueueStop(immediate: false)` — this drains the remaining queued audio. Wait until the queue actually stops (poll via a completion event or call with `immediate=false` which blocks-until-done).

For `WriteChunk(...)`:
1. Same EnsureInitialized + AudioQueueStart (only once).
2. Wait for a free buffer slot (callback-signaled), copy `count` samples in, enqueue. Do NOT stop/drain — caller controls the streaming loop.

For the callback:
- Keep a `Queue<IntPtr>` of free AudioQueueBuffer pointers, protected by `_lock`.
- The callback pushes the just-finished buffer onto the free queue and signals a `ManualResetEventSlim`.
- `GCHandle.Alloc(callbackDelegate)` to keep the managed delegate alive for the queue's lifetime; store on the instance, free in `Dispose()`.
- Pass `IntPtr.Zero` for `inCallbackRunLoop` so the callback fires on the AudioQueue's internal thread.

For `IsAvailable()`:
- Try calling `AudioQueueDispose(IntPtr.Zero, true)` inside `try { } catch (DllNotFoundException) { return false; } catch { return true; }` — any non-`DllNotFoundException` means the framework resolved (the call will return an error code, but we never see it as a managed exception unless the library is missing).
- Cheap alternative: just check `RuntimeInformation.IsOSPlatform(OSPlatform.OSX)`. We'll use the actual P/Invoke probe to be safe — if the framework path moves in a future macOS, IsAvailable correctly reports false.

NOTE on cross-platform safety: `DllImport("/System/Library/...")` is declared at type load, but the native library is only resolved on first call. The `IsAvailable()` static method is the only entry point that probes — and it catches `DllNotFoundException`. As long as no code path calls into CoreAudio on Linux, declaring the type is safe.
</implementation_strategy>
