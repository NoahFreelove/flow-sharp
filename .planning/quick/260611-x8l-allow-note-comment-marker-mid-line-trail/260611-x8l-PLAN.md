# Quick Task 260611-x8l — `Note:` trailing/mid-line comments

## Context

Composer report (web playground): `Note: <comment>` errors. Investigation: `Note:` already
works as a **line-start** comment (lexer arm since the base interpreter). What does NOT work
is `Note:` **trailing a statement** on the same line, e.g. `(play x)   Note: this plays it` —
there the `IsStartOfLineContent()` guard fails, `Note:` lexes as `Note` + `:` (Colon), and the
parser errors. Composer decision (2026-06-12): allow `Note:` mid-line / trailing.

## Change

`flow-lang/Lexing/SimpleLexer.cs`, the `Note:` arm inside `SkipWhitespaceAndComments()`
(runs at every token boundary): drop the `&& IsStartOfLineContent()` condition so `Note:`
starts a to-end-of-line comment wherever it appears as leading trivia for the next token
(line start OR trailing a token).

Scope: **only `Note:`** (the explicit ask). `TODO:` / `FIXME:` keep their line-start guard
for now (noted as a possible follow-up for consistency).

## Safety (verified)

- Only mid-line `Note:` in any `.flow` file is inside a `//` comment
  (`examples/generative/tidal_combinators.flow:89`) — never reached by the lexer.
- A bare mid-line `Note:` currently lexes as `Note` + `:` → parse error in practically all
  contexts, so making it a comment is strictly more charitable (no valid construct lost).
- Quoted strings lex via the `"` path before this check, so `"Note: ..."` stays a String.

## Tasks

1. Remove `IsStartOfLineContent()` from the `Note:` arm in `SimpleLexer.cs`.
2. Build `flow-lang`; verify:
   - `Note: hello` (line start) still a comment.
   - `(print "x") Note: trailing comment` parses + runs (trailing `Note:` ignored).
   - `String s = "Note: keep"` stays a String (quoted, not a comment).
3. Run `flow-lang.Tests` (lexer/parser suites) — no regressions.

## Verification

- `dotnet run -- -e '(print "ok") Note: trailing'` prints `ok`, no error.
- Existing line-start `Note:` tests + `.flow` files unaffected.
