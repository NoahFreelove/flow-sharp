# Flow DAW structured generators — 2026-10-04

P7-01 establishes the first real `@flowDaw` authoring boundary. This follows the
backend goal and the arrangement foundation; it does not complete Phase 7 or the
frontend-readiness goal. Previous goal turn made concrete model/history/persistence
progress; this turn adds generator implementation and end-to-end evidence.

## Implemented

- Shipped `flowDaw.flow` module, copied for desktop and embedded for the existing
  Web target. Import exposes normal procedure declarations and does not generate
  music, play output or write MIDI.
- `(dawResult song)` returns the default `main` score layer; `(dawResult "lead"
  song)` returns a named layer. These are normal `Dict<String, Song>` values;
  standard immutable `set`/`merge` can combine layers.
- Version-1 `GeneratorDescriptor` carries stable source ID and validated entry-point
  identifier. Its type currently describes composition generators only.
- Detached `GenerationContext` copies numeric parameters and retains revision,
  explicit seed, immutable project tempo/meter maps. The Flow entry receives a
  normal `Dict<String, Double>` with `tempoBpm`, `meterNumerator`,
  `meterDenominator`, `seed`, and `parameter:<id>` values. Initial tempo/meter are
  exposed in this first surface; complete map queries and tuning/asset context
  remain open rather than being silently synthesized.
- `FlowDawGenerator.Template` visibly imports `@flowDaw` and defines `generate` in
  existing Flow procedure syntax. No language grammar was added.
- `FlowDawGenerator.Build` creates a fresh engine, evaluates source, invokes the
  declared procedure with a host-injected context Value, then detaches named songs
  through CompositionCompiler. User data is never interpolated into invocation
  source. The entry identifier is validated and the private context identifier is
  generated by the host. Output retains no interpreter values or closures.
- Stable musical IDs derive from source/layer identity; output carries source and
  context revisions. Repeated builds of the same structure retain note identities.
- One time budget covers setup, invocation and detachment. Source length, named
  layer count, placements and authored notes have limits. Output note/placement
  limits are checked after detachment, so these are not hard memory allocation caps.
- `FlowDawGeneratorHost` reuses latest-request coordination, with one source per
  host and a semaphore that prevents overlapping engines even after the
  coordinator's termination grace. Failed/cancelled/timed-out/superseded jobs do
  not replace LastGood. Source/context/parameter changes must be submitted as a
  new request; the host does not watch document state itself.

## Actual authoring syntax

```flow
use "@flowDaw"
proc generate (Dict<String, Double>: context)
    section phrase { Sequence melody = | A4q C5q E5h | }
    Song score = [phrase]
    (dawResult "main" score)
end proc
```

A host supplies `new GeneratorDescriptor(1, sourceId, "generate")`, code revision,
context and time limit. The resulting named compositions can already feed the
prepared sine renderer; no MIDI serialization is involved. This is a library API,
not a new standalone CLI command or a persisted source transaction yet.

## Required follow-up

This host is cooperative, not a sandbox or hard process memory/deadline boundary.
General Flow code can still invoke explicitly imported side effects. Move this
structured result protocol through the existing process worker before using
arbitrary code alongside realtime playback; retain single-worker capacity and
kill/reap semantics. Add pre-detachment resource validation where possible.

The full contract still requires asset/tuning/map context, structured audio/graph
outputs, descriptor parameters/ports and dependency metadata, persisted source
acceptance as one undoable transaction, and clip binding reconciliation. Complete
these alongside the versioned device catalog/prepared graph and the shared
instrument → ordered effects → group/master live/offline path. Do not replace
those requirements with MIDI-only output or a DAW-only DSP implementation.
